# 中微子（Neutrino）项目概览

> 产品名：**中微子（Neutrino）**；内部代号仍为 **GhostScreen**（可执行文件、命名空间、MCP server key 暂不改）。
>
> 文档状态：v0.3（2026-10-23），P0 完成。项目定位为**开源（Apache-2.0）**，执行规划见 `07-开源项目规划.md`；P0 实测见 `spike/REPORT.md`。
>
> **P0 关键修正**：WGC 对完全离屏窗口会冻结；PrintWindow 离屏实时（p50≈12ms）。捕获顺序已改为 PrintWindow 主路径、WGC 仅可见/VDD。

## 1. 一句话

GhostScreen 给 Agent 一块**人类看不见的屏幕**：让应用窗口在系统里照常真实渲染，但不出现在人的显示器上；Agent 可以随时取图、点击、输入，而人继续自己的工作，不闪窗、不被抢焦点、不被抢鼠标。

## 2. 要解决的问题

现在的 computer-use agent 基本都建立在"共享同一块物理屏幕"这个前提上：

1. **视觉验证会闪窗**。前端 Agent 改完代码，需要打开浏览器截图确认渲染效果。浏览器窗口会真实地弹到人眼前，人正在写东西时被打断。
2. **人机互相打断**。Agent 的点击会移动真实光标、抢焦点；人的鼠标/键盘又会让 Agent 的下一步落空，双方都在猜对方的状态。
3. **一人一屏不现实**。给每个 Agent 配一台显示器/虚拟机成本太高，也没法在笔记本上随手用。
4. **共享屏幕 = 共享隐私与噪声**。截全屏会把人的聊天、邮件、密钥一起送给模型；Agent 的窗口也会出现在人的任务栏和 Alt-Tab 里。
5. **无法并行**。多个 Agent 共用一个光标，本质上只能串行。

核心洞察：Agent 需要的是**画面的像素**和**可控的输入通道**，不是"显示器"这个物理对象。只要窗口在 Windows 里是"活的"（DWM 正常合成它），我们就可以在人看不到的地方把它渲染出来并取走像素。

## 3. 目标（v1）

- 提供一个本地守护进程 + MCP 服务器，Agent 通过工具调用完成：
  - 打开网页 / 启动桌面应用 / 接管指定窗口；
  - 获取该窗口的**真实渲染截图**（含元数据、稳定性等待、空白/过期检测）；
  - 获取结构化观测（网页 DOM / 原生 UIA 元素树）；
  - 执行点击、输入、按键、滚动、拖拽、等待；
  - 关闭并恢复现场。
- 目标窗口全程**不出现在任何物理显示器上**，不进入任务栏/Alt-Tab（可配置），不抢前台焦点，不移动真实光标，不修改剪贴板。
- 多个 target 并行，人类正常工作不受影响。
- 托盘 + 极简状态页：人可以看到 Agent 正在看的画面、操作记录，并有一键急停（完整 Dashboard 后置到 v1.x）。
- **开源（Apache-2.0）**：无遥测、无账号、无付费墙、无云依赖；工程质量、兼容性和可维护性优先于功能数量。

## 4. 非目标

- 不做远程桌面、游戏串流、云桌面。
- 不承诺支持独占全屏游戏、DRM/受保护内容、带硬件覆盖层的播放器。
- 不做跨操作系统（先 Windows 11）。
- 不修改/注入目标进程（不做 DLL 注入、不做 API Hook）。
- 不自研内核驱动。虚拟显示器作为**可选**增强，通过检测用户已安装的 IddCx 虚拟显示器实现，不在 v1 捆绑驱动。
- 不保证对所有应用的输入都能 100% 隔离——输入能力是分层的，且必须如实上报（见 `01`、`02`）。
- 不做多用户服务器化部署（单用户、本地回环）。
- 不按商业产品设计：无付费墙、无账号体系、无云服务、无遥测。
- v1 不自研/不捆绑虚拟显示器驱动；只检测用户已安装的 VDD（v1.x 可选）。

## 5. 典型场景

### A. 前端视觉验证（第一优先级）

Agent 启动 dev server，用**无头 Edge**打开 `http://localhost:3000`，按 375/768/1440 三个视口截图，读取 console 错误和失败请求，发现移动端横向溢出后改 CSS，再次截图确认。整个过程屏幕上**一个浏览器窗口都不会出现**，人可以在同一个屏幕上继续写代码。

### B. 桌面应用后台操作

Agent 需要在一份内部 Win32 工具里录入数据：启动一个新实例 → 停泊到屏幕外 → 截图 → UIA 找到输入框并设值 → 点击保存 → 截图确认。前台窗口、光标位置、剪贴板全程不变。

### C. 多 Agent 并行

三个 Agent 各自持有 target（一个网页、一个记事本、一个 Electron 应用），各自截图/操作。人的屏幕上只有自己的窗口；状态页里能看到三块"虚拟屏"的最近画面和操作日志。

## 6. 产品形态

| 组件 | 形态 | 作用 |
|---|---|---|
| `GhostScreen Daemon` | 托盘程序（登录自启） | 真正干活的本地进程：停泊、捕获、输入、HTTP/WS、极简状态页 |
| `gs mcp` | stdio 子进程 | 给 Agent 客户端用的 MCP 服务器，桥接到 daemon |
| `gs` | CLI | 调试、脚本、验收测试 |
| 状态页 | 本地网页（127.0.0.1） | target 列表、最近截图、操作记录、急停（v1.0 极简版） |
| 可选 VDD 适配 | 检测用户自装虚拟显示器 | 对离屏表现不佳的应用做保真兜底 |

> 为什么不是 Windows 服务：服务运行在 Session 0，看不到也操作不了用户桌面上的窗口。必须跑在交互式用户会话里。

## 7. 成功标准（可测量）

1. **不可见**：以主显示器 DXGI 桌面复制逐帧检测，target 存在期间，其窗口区域从未出现在物理屏幕上（启动瞬间允许 ≤1 帧的例外，需测量并优化；默认流程应为 0）。
2. **不打扰**：整个测试期间，`GetForegroundWindow` 不变、`GetCursorPos` 不变、剪贴板序列号不变；测试脚本持续向人类窗口输入文字不丢失。
3. **真实性**：同一页面/应用在可见状态下的截图与 GhostScreen 截图做像素对比，差异仅允许来自时间/动画（静止画面应完全一致）。
4. **可用性**：一个真实的 MCP 客户端能在 10 分钟内跑通「打开网页 → 截图 → 按元素点击 → 断言文本 → 关闭」。
5. **性能**：1280×800 截图 p50 ≤ 150 ms、p95 ≤ 400 ms（本机，PNG）；常驻空闲 CPU ≈ 0%。
6. **安全**：默认只监听回环 + 令牌；任何 target 创建都有可见指示；急停能立即终止所有捕获与输入。
7. **开源可用性**：新用户按 Quick Start 在 5 分钟内跑通；支持矩阵内 6–8 个应用；每个 release 有 SHA256、CHANGELOG 和已知限制。

## 8. 设计原则

1. **不可见优先，不抢焦点优先**。做不到就不做，并明确告诉调用方，而不是偷偷把窗口弹出来。
2. **人类优先**。人的前台窗口、光标、剪贴板、输入流是最高优先级；宁可 Agent 失败，也不打扰人。
3. **真实像素**。网页用真实浏览器渲染，应用用系统真实合成结果；不做 DOM 重绘的"假截图"。
4. **诚实降级**。每个 target 都上报能力矩阵（capture/observe/input）和降级原因，Agent 据此决策。
5. **本地、可审计、可急停**。默认不联网、不上传；操作留痕；一键停止。
6. **先垂直切片，再扩兼容性**。每个里程碑都能演示一个完整闭环，而不是先堆一层"框架"。

## 9. 术语

| 术语 | 含义 |
|---|---|
| Target | 一个被 Agent 托管的窗口或网页实例，有唯一 `target_id` |
| Park（停泊） | 把窗口移动到人看不到但系统仍认为它可见的位置，并保持非最小化 |
| Capture Backend | 取像素的实现，如 WGC / PrintWindow / CDP / VDD |
| Observation | 结构化观测，网页 DOM 或原生 UIA 元素树 |
| Input Strategy | 输入实现，如 UIA / CDP / 窗口消息 / SendInput |
| Capabilities | 某个 target 当前实际可用的捕获/观测/输入方式 |
| Settle | 操作后等待画面/网络稳定再返回 |
| VDD | Virtual Display Driver（IddCx 间接显示驱动） |
| WGC | Windows.Graphics.Capture，Windows 10 1803+ 的窗口/显示器捕获 API |
