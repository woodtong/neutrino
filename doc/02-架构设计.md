# 架构设计

## 1. 目标与约束

**必须成立**
- 目标窗口不出现在物理显示器上；不抢前台焦点；不移动真实光标；不修改剪贴板。
- 截图是系统真实合成/渲染结果，不是 DOM 重绘的近似图。
- 多 target 并行，互不干扰；人类可以同时正常使用电脑。
- 本地运行，默认不联网；有可见的运行指示与急停。
- 失败时明确降级并上报原因，不"装作成功"。

**硬约束**
- 必须运行在**交互式用户会话**（Session 1+），不能是 Windows 服务。
- 不能注入目标进程、不能 Hook、不能绕过受保护内容。
- 捕获/输入能力受应用族、窗口状态、完整性级别影响，必须按 target 上报。
- v1 不要求管理员权限；提权窗口不支持（明确报错）。

## 2. 进程与会话模型

```
┌───────────────────────── 交互式用户会话（Session 1） ─────────────────────────┐
│                                                                               │
│  Agent / MCP 客户端                                                           │
│      │ stdio (JSON-RPC)                                                       │
│      ▼                                                                        │
│  gs-mcp（无状态桥） ─── named pipe ───► GhostScreen Daemon（托盘程序）         │
│                                            │                                   │
│                                            ├─ TargetRegistry / SessionActor   │
│                                            ├─ ParkingManager ── SetWindowPos ──┼──► 屏幕外的窗口
│                                            ├─ CaptureEngine ── WGC / PrintWin ─┼──► 像素
│                                            ├─ Observation ── UIA / CDP ────────┤
│                                            ├─ InputRouter ── Msg/CDP/UIA(auto-restore)/SendInput
│                                            ├─ HTTP/WS 127.0.0.1 + 状态页      │
│                                            ├─ Audit log（JSONL）              │
│                                            └─ Watchdog（窗口状态/帧新鲜度）    │
│                                                                               │
│  人类的窗口、前台焦点、光标、剪贴板 —— 不被触碰                               │
└───────────────────────────────────────────────────────────────────────────────┘
```

**为什么是托盘程序而不是服务**
Windows 服务运行在 Session 0，与用户桌面隔离：枚举不到用户窗口、截不到图、收不到输入。任何"服务 + 代理"的拆分最终也要在用户会话里放一个代理，不如直接让 daemon 跑在用户会话，用登录自启解决可用性。

**为什么 MCP 是独立进程**
MCP 客户端按需拉起 `gs mcp`，通过命名管道连 daemon。好处：Agent 重启不影响 daemon 和已停泊的窗口；daemon 崩溃时 MCP 进程能明确报错；stdio 的 JSON 不会污染 daemon 日志。

**可选提权**
默认不提权。需要操作管理员窗口时，提供显式的 `gs daemon --elevated`（或独立 helper），并在 UI/文档中说明风险。不做静默提权。

### 2.1 本地状态端点（0.3.0-dev 首版）

当前是单进程 MCP，没有独立 daemon；为了让人能看到 Agent 在做什么并提供急停，MCP 进程内起了一个**只绑 127.0.0.1** 的最小 HTTP 端点：

- 实现：原始 `TcpListener` + 手写 HTTP/1.1（无 Http.sys URL ACL、不需要管理员、无 ASP.NET 依赖）。
- 认证：每次启动生成 128-bit 随机 token；页面与所有 API 都必须带 `?token=` 或 `X-GhostScreen-Token`，比较用固定时间。
- 端点：`GET /`（1s 状态轮询 + 5s 缩略图刷新）、`GET /api/status`（targets/能力/恢复摘要/版本/uptime）、`GET /api/screenshot?target_id=`（单 target PNG，原生 2s 超时、web 6s 上限；hung 返回 409，超时 504）、`POST /api/panic`（close_all）。
- 缩略图限速：原生截图会强制重绘，2–5fps 对被动状态页成本过高；首版用 5s（0.2fps），后续需要连续帧时再评估限流/增量编码。
- 发现：URL+token 写到 `%LOCALAPPDATA%\GhostScreen\status.json`，并在 MCP stderr 打印；正常退出删除该文件。
- 边界：只绑 loopback；token 在 URL 里，可能进入浏览器历史，仅适合本机；没有截图流（后续用 target 截图端点，2–5fps，需单独限流）。
- 生命周期：跟随 MCP 进程；没有独立 daemon 的“关掉 MCP 仍可查看/急停”能力，这一点在 P4-01 独立 daemon 决策后再补。
- 托盘：`GhostScreen.Tray.exe` 是**独立小进程**，每 2s 读 `status.json` 并轮询同一边界；不持有 target，所以 MCP 退出后显示“未运行”。菜单提供打开状态页、急停、退出；这样不做 daemon 也能给人一个状态指示与急停入口。

## 3. 组件

| 组件 | 职责 | 关键点 |
|---|---|---|
| `TargetRegistry` | target 的创建、查找、生命周期、TTL | 线程安全；按 client/session 隔离 |
| `SessionActor` | 单个 target 的串行执行器 | 捕获与输入串行化，避免"边点边截"的竞态 |
| `WindowRegistry` | 枚举/识别窗口、进程、类名、cloak 状态 | 过滤自身窗口、零尺寸、cloaked |
| `ParkingManager` | 保存原状态、停泊、校验、还原、watch | 任何时刻可还原；崩溃后可恢复 |
| `CaptureEngine` | 选择后端、取帧、稳定性、编码、元数据 | 后端可插拔；空白/过期检测 |
| `ObservationEngine` | UIA 树 / DOM 快照 / 元素引用 | 引用带 epoch，过期即报错 |
| `InputRouter` | 按 target 能力选择输入策略、坐标换算、验证 | 绝不静默降级到 SendInput |
| `WebRuntime` | 无头 Edge 生命周期 + CDP | 独立 profile；可控视口；console/network |
| `DaemonApi` | 本地 HTTP/WS、MCP 桥、极简状态页 | 127.0.0.1 + 令牌 + Origin 校验 |
| `Audit` | 操作与错误日志 | JSONL，轮转；不含截图内容 |
| `Watchdog` | 检查窗口是否被最小化/移动/cloak、帧是否过期 | 自动重停泊/降级；不还原人的窗口 |

## 4. Target 生命周期

```
             ┌──────────────┐
   create ──►│  launching   │──失败──► error
             └──────┬───────┘
                    │ 找到主窗口
                    ▼
             ┌──────────────┐
             │   parking    │──失败──► error（说明原因）
             └──────┬───────┘
                    ▼
             ┌──────────────┐   帧过期/窗口异常    ┌────────────┐
             │    ready     │◄────────────────────►│  degraded  │
             └──────┬───────┘   自动恢复            └────────────┘
                    │ capture / act（串行）
                    ▼
             ┌──────────────┐
             │   closing    │──► closed（还原或终止）
             └──────────────┘
```

**规则**
- `ready` 才允许截图/操作；`degraded` 允许有限的只读截图但必须带 `degraded_reason`（`TARGET_HUNG` 例外：全部操作快速失败）。
- 任何状态都可以被 `close` 中断；`close` 必须幂等。
- target 有 TTL（默认 30 分钟无操作自动关闭），防止孤儿窗口。
- 原生 target 连续 2 次捕获超时（`CAPTURE_TIMEOUT`）后标记 `degraded / TARGET_HUNG`；此外 `CaptureEngine.Capture` 在入口调用 `IsHungAppWindow`，命中即立即降级（该检查必须在 `WindowEnumerator.Describe` 之前，否则 Describe 会清掉无响应标记）。此后 capture/observe/input 立即返回 `TARGET_HUNG`，不再创建新的超时线程，`close` 仍会还原窗口。重新 attach 可恢复（重新 observe/ref 也需重做）。
- `attach_window` 在移动窗口前先 `IsHungAppWindow`；挂起窗口直接 `TARGET_HUNG`，避免 `SetWindowPos` 卡住。捕获/输入阶段仍可能在极窄的竞态里遇到刚挂起的窗口，此时靠超时与降级兜底。
- `WindowInfo.DpiAwareness` 通过 `GetWindowDpiAwarenessContext` 读取；`Unaware` 目标在 DTO 带 `DPI_UNAWARE` warning。DPI-unaware 的黑边/缩放修复仍未做（P4-04，单屏硬件受限）。
- daemon 退出时还原所有 target；崩溃后下次启动读取 `state.json` 做恢复。

### 4.1 崩溃恢复（0.3.0-dev）

- 日志文件：`%LOCALAPPDATA%\GhostScreen\state\targets.json`，每次 park/open_web 后写入；先写 `.tmp` 再原子替换，避免半写文件。
- 原生 target 记录：hwnd、pid、进程名、窗口类、标题、`WINDOWPLACEMENT`、原始 exstyle、是否可见。启动时校验 hwnd 仍有效、pid 未变、窗口类一致，才 `SetWindowPlacement` 还原；任一不符则跳过并报告。
- web target 记录：浏览器 pid、进程启动时间、profile 路径、URL。启动时只杀“pid + 启动时间 + 进程名 msedge”都匹配的进程（防 pid 复用），随后删除 profile。
- 清理：`web-profiles` 下超过 24 小时的目录在启动时删除（兜底崩溃前没来得及记账的情况）。
- 损坏的 journal 不阻塞启动：移到 `targets.json.corrupt-<ts>`，继续以空状态启动。
- 写入失败返回 `STATE_WRITE_FAILED`，并撤销本次 attach/open（避免“以为可恢复、实际没记账”）。
- 启动恢复结果写入 stderr；`TargetManager.LastRecovery` 暴露 `restored/skipped/killedBrowsers/deletedProfiles/sweptProfiles`。
- 当前是**单进程**假设：两个 MCP 实例共享同一 journal 会互相清理；多客户端 daemon 落地后需要按实例分区。

## 5. 停泊管理器（ParkingManager）

### 5.1 停泊算法

```
park(target):
  1. 前置检查：IsWindow / IsWindowVisible / !IsIconic / DwmGetWindowAttribute(CLOAKED)==0
  2. 保存现场：GetWindowRect、GetWindowPlacement、STYLE/EXSTYLE、DPI、所在显示器
  3. 选择停泊点：
     - 目标：完全位于虚拟桌面并集之外，且尽量靠近原显示器以保持 DPI
     - 单屏：x = virtualScreen.Right + 64，y = 原窗口 y（或显示器 Top+32）
     - 多屏：优先放在"虚拟桌面右边界之外、与原显示器 Y 区间重叠"的位置
     - 禁止使用 -32000（Windows 自己用作最小化位置，部分应用/DWM 有特殊处理）
  4. 若窗口当前隐藏/最小化（仅限我们有权限的 target）：先恢复到 normal，再停泊
  5. SetWindowPos(hwnd, NULL, parkX, parkY, w, h,
       SWP_NOACTIVATE | SWP_NOZORDER | SWP_NOOWNERZORDER)
  6. 可选隐藏任务栏/Alt-Tab 痕迹：WS_EX_TOOLWINDOW + SetWindowPos(SWP_FRAMECHANGED)
     （只对 agent 启动的窗口默认启用；接管人的窗口时默认不动样式）
  7. 校验：矩形完全在虚拟桌面外、IsWindowVisible=true、!IsIconic、未 cloaked
  8. 启动 watch（2s 周期）：位置漂移/cloak/最小化 → 重新停泊（带退避），连续失败 → degraded
```

### 5.2 启动流程（避免闪窗）

目标：应用自己的窗口创建后**第一帧就不出现在人眼前**。

```
launch(app):
  A. 首选：CreateProcess(CREATE_SUSPENDED?) + STARTF_USESHOWWINDOW(SW_HIDE)
     - 等待属于该 PID 的顶层窗口出现（最长 10s）
     - 移动窗口到停泊点 → ShowWindow(SW_SHOWNOACTIVATE)
     - 对 Chromium 系可额外传 --window-position=<parkX>,<parkY> --window-size=w,h
  B. 若应用在隐藏状态下不创建窗口（少数）：
     - 以 SW_SHOWMINNOACTIVE 启动（任务栏出现按钮但不弹窗）
     - 找到窗口后立刻移动 + 恢复，再隐藏任务栏按钮
  C. 超时/失败：终止进程树，返回 LAUNCH_FAILED，不留下可见窗口
```

> 启动瞬间仍可能有极短闪烁（取决于应用的首帧时机）。M0/M1 要用高速屏幕复制测量并优化；验收标准允许 ≤1 帧，但目标为 0。

### 5.3 还原

- 用保存的 `WINDOWPLACEMENT` + rect 还原位置、大小、显示状态；
- 还原 `WS_EX_TOOLWINDOW` 等被动过的样式；
- 对"我们启动的进程"默认终止；对"接管的窗口"只还原、不关闭；
- 还原失败（窗口已销毁/进程退出）只记日志，不阻塞。

### 5.4 停泊的已知风险

| 风险 | 表现 | 处理 |
|---|---|---|
| 应用自我纠正位置 | 窗口被拉回屏幕内 | watch 检测 → 重停泊；两次失败 → 用 VDD 或报 `PARK_UNSTABLE` |
| 多显示器 DPI 变化 | 窗口布局重排、截图尺寸变化 | 停泊点尽量保持原显示器；上报 `dpi_scale`；M7 专项测试 |
| 窗口被 cloak | 黑帧 | 禁止移到其他虚拟桌面；检测后恢复 |
| 最小化/隐藏 | 黑帧 | 拒绝捕获并报 `NOT_RENDERABLE`，建议恢复 |
| 任务栏/Alt-Tab 残留 | 人看到多余条目 | 自建窗口默认 `WS_EX_TOOLWINDOW` + `ITaskbarList::DeleteTab` |
| 应用把"离屏"当异常 | 暂停动画/降频 | 受控 Chromium 加禁节流参数；watch 检测帧停滞后降级/建议 VDD |

## 6. 捕获引擎（CaptureEngine）

### 6.1 后端接口

```csharp
public interface ICaptureBackend
{
    string Name { get; }                       // "wgc" | "printwindow" | "vdd" | "cdp"
    bool Supports(Target target);
    Task<Frame> CaptureAsync(Target target, CaptureOptions options, CancellationToken ct);
}

public sealed record Frame(
    byte[] Bgra, int Width, int Height, long TimestampTicks,
    string Backend, CaptureMeta Meta);
```

### 6.2 后端选择策略

```
if target.kind == web:                       cdp
else if target.onVdd && vddAvailable:        vdd (WGC monitor / DXGI duplication)
else if target.isVisibleOnMonitor:           wgc (live)
else:                                        printwindow (default offscreen)
```

- **P0/P1-11 实测**：WGC 对完全离屏窗口只保留最后一帧；PrintWindow 在离屏状态下实时（FixtureApp 8/8 帧变化，p50≈12ms；Edge GUI 完整页面；Calculator 完整 UWP；VS Code 只有 chrome）。因此**离屏默认 PrintWindow**，WGC 仅用于可见窗口/VDD；Electron 用 CDP。
- 选择不是一次性的：PrintWindow 连续空白/失败 → 若是 Electron/Chromium 且有 CDP 则切 CDP；若窗口可见/VDD 则尝试 WGC；否则 `degraded` 并上报原因。
- PrintWindow 是拉取式：每次调用触发一次绘制；大窗口/挂起应用可能慢或阻塞，必须加超时/隔离。
- 每个 target 记录最近成功的后端与耗时，供 API 查询。

### 6.3 窗口状态门槛

截图前必须通过：
- `IsWindow(hwnd)` 为真；
- `IsWindowVisible` 为真；
- `!IsIconic(hwnd)`；
- `DwmGetWindowAttribute(hwnd, DWMWA_CLOAKED) == 0`；
- `GetWindowDisplayAffinity` 不含 `WDA_EXCLUDEFROMCAPTURE`；
- 窗口尺寸 > 0 且 < 上限（例如 8192×8192）。

任一不满足 → 结构化错误，不返回黑图。

### 6.4 帧新鲜度与稳定性

Agent 做视觉验证最怕"截到旧画面"。策略：

1. **PrintWindow 每次调用就是一次新帧**（拉取式）：用内容 hash + `wait_stable` 判断稳定；WGC 的 `FrameArrived` 序号只适用于可见/VDD 场景。
2. **稳定性等待**（默认开启，`wait_stable_ms` 默认 250ms，上限 3s）：
   - 以 50ms 间隔取帧，计算内容 hash（可先缩小到 64×64 灰度，降低噪声）；
   - 连续 N 次 hash 相同 → 认为稳定，返回最后一帧；
   - 超时 → 返回当前帧，并在元数据标 `stable:false`。
3. **过期检测**：WGC 离屏会冻结；如果 target 在离屏且用了 WGC，连续 hash 相同且无新帧 → 标 `stale_suspect:true`，切 PrintWindow。
4. **空白检测**：颜色方差过低（全黑/全白/单色）→ `blank:true`，不当作成功截图。
5. **操作后 settle**：点击/输入后默认等待画面稳定（最多 2s）；网页额外支持 `networkidle`。

### 6.5 图像处理

- 默认裁剪到**客户区**（网页是视口），可选包含标题栏/边框（`include_frame`）。
- 默认等比缩放到最长边 ≤ 1568 px（适配主流视觉模型），保留 `image_scale` 元数据；`scale:"native"` 取原尺寸。
- PNG 无损（默认）；JPEG 仅用于实时预览流（质量 80）。
- 缩放用高质量重采样（WIC Fant / Lanczos），避免文字发虚。
- 可选合成"虚拟光标"（最后一次 Agent 点击位置），方便验证 hover/点击落点；默认关闭。

## 7. 观测引擎（ObservationEngine）

### 7.1 UIA（原生应用）

- 使用 UI Automation COM（`CUIAutomation8`），带 `CacheRequest` 批量取属性，避免逐节点跨进程往返。
- 输出扁平化元素列表（默认最多 300 个、仅可交互元素），字段：
  `ref`（本次观测内有效，如 `e12`）、`role`、`name`、`value`、`bounds`（屏幕物理像素）、`enabled`、`focused`、`patterns`、`depth`。
- `ref` 与 `observation_epoch` 绑定；操作时如果 epoch 已过期 → `ELEMENT_STALE`，要求重新 `observe`。
- 元素解析：按 RuntimeId + 名称 + 边界三重匹配，避免 UI 变化导致误点。

### 7.2 DOM（网页）

- CDP `DOM.getDocument` + `Runtime.evaluate` 生成"可交互元素清单"（按钮、链接、输入、下拉、可点击区域），带稳定的 CSS selector 与 bounding box。
- 也提供 `Accessibility.getFullAXTree` 作为语义补充（可选）。
- 默认过滤不可见元素；输出上限 300 条。

### 7.3 为什么需要观测

纯像素点击对模型来说脆弱：滚动、遮挡、动画都会让坐标失效。元素引用 + 语义动作（UIA Invoke / CDP click）能显著提高成功率；像素坐标作为兜底。两者共用同一个 `target_id` 与坐标系。

## 8. 输入路由（InputRouter）

### 8.1 策略链

```
click(target, point|ref|selector):
  1. web + cdp                → Input.dispatchMouseEvent（CSS 像素）
  2. native ref/name + HWND   → BM_CLICK / WM_MOUSEMOVE+DOWN+UP（客户区），不激活窗口
  3. native ref/name 无 HWND  → UIA Invoke/Toggle/SelectionItem/ExpandCollapse，执行后恢复前台
  4. native point + HWND      → WM_MOUSEMOVE+DOWN+UP（客户区）
  4b. native point 单 HWND    → UIA AtPoint 找最小可执行元素，执行后恢复前台
  5. 显式 interactive         → SendInput + 焦点切换（危险模式，未实现）
  6. 否则                     → ELEMENT_NOT_ACTIONABLE / INPUT_UNSUPPORTED

type(target, text):
  1. web + cdp                → Input.insertText（或逐键 dispatchKeyEvent）
  2. native EDIT/RICHEDIT     → WM_SETTEXT（不激活窗口）
  3. native 无 HWND           → UIA ValuePattern，执行后恢复前台
  4. interactive              → SendInput（未实现）
  5. 否则                     → ELEMENT_NOT_ACTIONABLE / INPUT_UNSUPPORTED
```

**执行优先，拒绝兜底**：调用方要的是“这一次调用真的做了事”。只有目标挂起、受保护、不可见，或控件确实没有可执行 pattern 时才拒绝；不因为用户当前在打字而拒绝。

**绝不静默使用 SendInput**。`interactive` 必须是调用方显式参数，且 daemon 侧有开关；默认关闭。

### 8.1.1 焦点安全（2026-10-24 实测修订）

关键事实：`WS_EX_NOACTIVATE` 只阻止**用户点击**激活窗口，挡不住程序调用 `SetForegroundWindow`。实测 WinForms 和 WPF 的 UIA provider 在 `InvokePattern.Invoke`、`ValuePattern.SetValue`、`TogglePattern.Toggle`、`SelectionItemPattern.Select` 时都会激活目标窗口，即使窗口已带 `WS_EX_NOACTIVATE`。另一方面，把 `WM_LBUTTONDOWN`/`WM_CHAR` 直接发给未激活的 WPF 顶层 HWND 不会触发按钮或输入。因此“WPF/UWP 完全零激活地执行”目前没有通用办法。

策略是“先找不激活的路，再执行并恢复，最后才拒绝”：

1. **UIA 只做观测**（`Snapshot`/`FindByName`/`FindByAutomationId` 只读，不激活）。
2. **动作消息优先**：用 UIA bounds 找到 HWND 子控件，发 `BM_CLICK`/`WM_*`/`WM_SETTEXT`；这些消息在实测中不改变前台，覆盖经典 Win32/WinForms。
3. **无 HWND 自动走 UIA**：WPF/UWP/自绘控件按可用 pattern 执行（Invoke → Toggle → SelectionItem → ExpandCollapse；文本用 ValuePattern）。坐标点击同样回退到 UIA `AtPoint`，按屏幕点找最小可执行元素。不需要额外授权参数，也不因用户活跃拒绝。
4. **FocusGuard 恢复**：动作前记录前台；最多等 500ms 观察目标是否激活；若前台仍是 target，用 `SetForegroundWindow`/`AttachThreadInput` 恢复，并做 100ms 稳定校验；不用强制的 `SwitchToThisWindow`。若人类已切到第三个窗口，尊重该选择；恢复失败返回 `focus:"stolen"` + `FOCUS_STOLEN` 警告，但动作已执行。
5. **严格模式**：`strict_no_focus_steal=true` 时，需要 UIA 的动作直接返回 `FOCUS_STEAL_NOT_ALLOWED`，不执行。这是给“绝对不接受焦点切换”的用户的可选策略，不是默认。
6. **最后兜底**：控件没有任何可执行 pattern → `ELEMENT_NOT_ACTIONABLE`；目标挂起/受保护/不可见沿用既有错误码。
7. 消息路径不套 guard：消息不激活，旧 guard 每次多等 160ms，且可能无谓切前台。

### 8.2 坐标系

Agent 默认用**截图图像坐标**点击（因为它看到的是图）。转换链：

```
image px → client px（除以 image_scale、减去 client_origin_in_image）
         → screen px（ClientToScreen）
         → 后端输入坐标（消息用 client，CDP 用 CSS px，SendInput 用 screen）
```

- 原生窗口若 DPI-unaware，Windows 会做 DPI 虚拟化；我们统一用 PerMonitorV2 进程并按物理像素计算，必要时用 `PhysicalToLogicalPointForPerMonitorDPI`。
- 网页：CDP 使用 CSS 像素；`image px / deviceScaleFactor / image_scale` 得到 CSS px。
- 每次操作后返回 `resolved_point`（图像/客户区/屏幕三套坐标），便于调试。

### 8.3 操作后验证

- 默认 `settle`：等待画面稳定（最多 2s），并返回 `changed:true/false`（点击前后 hash 差异）。
- 若 `ref` 来自 UIA，可在操作后再次读取该元素的 `value/state` 做语义验证。
- 坐标点击失败（无变化）时，不自动重试（避免重复提交）；返回 `likely_noop:true` 供 Agent 决策。

## 9. Web 运行时（无头 Edge + CDP）

### 9.1 启动（0.2.0-p0 实现）

```
msedge.exe
  --headless=new
  --remote-debugging-port=0
  --user-data-dir=%LOCALAPPDATA%\GhostScreen\web-profiles\<guid>
  --window-size=1280,800
  --hide-scrollbars --mute-audio
  --disable-backgrounding-occluded-windows
  --disable-renderer-backgrounding
  --disable-background-timer-throttling
  --no-first-run --no-default-browser-check
  about:blank
```

- 端口：`--remote-debugging-port=0`，轮询 profile 下的 `DevToolsActivePort` 第一行取真实端口；不解析 stderr，避免本地化/缓冲问题。
- 每个 target 独立临时 profile，关闭时先 `Browser.close`，再杀进程树，最后删 profile（重试 5 次）。
- URL **不进入命令行**：浏览器固定开 `about:blank`，目标 URL 经 CDP `Page.navigate` 打开；URL 必须是 http/https/file/about，且不能以 `-` 开头。
- 目前只发现 Edge（Program Files (x86)、Program Files、LocalAppData 的 Edge/Beta/Dev）；没有 Edge → `BROWSER_NOT_FOUND`。Chrome 回退未实现。
- DPR/移动端模拟通过 `Emulation.setDeviceMetricsOverride`，不传 `--force-device-scale-factor`。

### 9.2 能力（已实现 / 计划）

已实现：
- 视口：`Emulation.setDeviceMetricsOverride`（width/height/deviceScaleFactor/mobile）；导航后重新应用请求视口，并重置 `captureBeyondViewport` 留下的页面缩放。
- 导航：`Page.navigate` + `document.readyState=complete` + `document.fonts.ready` + 最多 3s 的网络静默（300ms 无在途请求）。
- 截图：`Page.captureScreenshot` 视口/整页/任意 clip（CSS 像素，16384 上限），PNG 字节直接返回 MCP；截图后恢复视口。
- 多视口：`snapshot` 在一次调用内切换视口、逐张截图、检测 `horizontal_overflow` 并列出最多 5 个越界元素，结束后恢复原视口。
- 观测：DOM 可交互元素（button/a/input/textarea/select/role=button/contenteditable/onclick）+ 稳定 CSS path + bbox + 可见性/零尺寸过滤。
- 输入：`Input.dispatchMouseEvent`（click/drag）、`Input.synthesizeScrollGesture`（滚动）、`Input.dispatchKeyEvent`（含修饰键）、React 兼容的赋值（native setter + input/change）。
- 诊断：`Runtime.consoleAPICalled`（最多 500 条）；`Network.loadingFailed` 与 4xx/5xx（最多 200 条）。
- 生命周期：target 关闭即关浏览器；EOF/close_all 清理全部；100 次开关压力测试 0 失败、无 profile 残留。
- 外部 attach：`attach_cdp` 连接已在运行的 Chromium/Electron DevTools 端口（VS Code 等），不启动、不关闭浏览器；`close_target` 只 detach。外部进程死亡后操作返回 `TARGET_CLOSED`，死 target 仍可安全关闭。
- 稳定性：Playwright 风格的“每个 target 一条 CDP 连接 + 串行操作”；关闭时 `Browser.close` → 杀进程树 → 删 profile。

计划：
- 整页截图与有头 Edge 的像素 diff。
- `Accessibility.getFullAXTree`、跨 iframe DOM/网络。
- 下载/权限/证书策略；Chrome 回退。
- recipes 文档（Edge/VS Code 启动参数）。

### 9.3 限制

- 无头模式不渲染系统字体差异？仍使用真实浏览器渲染，字体/布局与有头一致（同一引擎）。
- 某些站点检测 `HeadlessChrome` UA；默认使用正常 UA，可配置。
- 文件下载、权限弹窗、证书错误需要显式策略（默认拒绝下载，允许自签证书需参数）。
- 跨域 iframe 的 DOM 观测受限（CDP 可跨 frame，但需要遍历 execution context）。

## 10. 可选：虚拟显示器（VDD）集成

**定位**：保真兜底，不是 v1 必需。

- 启动时枚举显示器（`EnumDisplayDevices` / `QueryDisplayConfig`），识别 VDD（设备字符串含 Virtual/Parsec/MTT 等）。
- 提供 `--virtual-monitor <id>`：新 target 默认停泊到该显示器，而不是屏幕外。
- 捕获：WGC 显示器捕获（该输出）或 DXGI Desktop Duplication；窗口矩形已知，直接裁剪。
- 输入：仍走 UIA/CDP/消息；只有"独占输入模式"才用真实 SendInput，并把光标临时放到虚拟屏坐标（人看不见，但系统光标位置会变，必须显式授权）。
- 安全：不自动安装驱动；检测不到就报 `VDD_NOT_FOUND` 并回退离屏。
- 显示设置里会出现一块额外显示器（这是 VDD 的固有痕迹），文档需说明。

## 11. 安全与隐私

| 面 | 措施 |
|---|---|
| 监听面 | 仅 `127.0.0.1`；命名管道 ACL 限定当前用户；拒绝非本机 Origin（防 DNS rebinding/CSRF） |
| 认证 | 随机 256-bit token，存于 `%LOCALAPPDATA%\GhostScreen\token`（ACL 仅当前用户）；HTTP `Authorization: Bearer`，WS 用子协议携带 |
| 授权 | 创建 target 即授权；接管**已有**人的窗口必须 `confirm:true` + 托盘提示；默认不提供整屏捕获 |
| 可见性 | 托盘图标变色/计数；状态页列出所有 target 与最近操作；全局急停热键（默认 `Ctrl+Alt+Shift+K`） |
| 审计 | JSONL：时间、client、target、动作、坐标、结果、耗时；不记录输入文本（可配置脱敏）与截图内容 |
| 提权 | 默认不提权；提权模式需显式启动并提示风险；拒绝静默提权 |
| 数据 | 截图默认只在内存；`save_to` 才落盘；不上传、不遥测 |
| 清理 | target 关闭/daemon 退出必须还原窗口、终止自建进程、删除临时 profile |
| 威胁模型 | 同用户的本地进程本来就能做任何事，token 主要防浏览器页面/局域网；不承诺对抗恶意本地进程 |

## 14. 关键决策记录（ADR）

| # | 决策 | 理由 | 代价 |
|---|---|---|---|
| 001 | **C# / .NET 8** | Win32/WinRT/UIA/COM 互操作成熟；开发速度快；单一运行时；WGC 示例丰富 | 自包含发布体积较大（~70MB） |
| 002 | **离屏停泊 + PrintWindow 主捕获（WGC 仅可见/VDD）** | P0 实测 WGC 离屏冻结、PrintWindow 离屏实时（p50≈12ms）；无需驱动 | PrintWindow 对部分应用可能全黑/阻塞；少数应用需 VDD |
| 003 | **网页目标用无头 Edge + CDP，不接管人的浏览器** | 真正零窗口、可拿 DOM/console/network、输入可靠 | 需要浏览器；某些站点对无头敏感 |
| 004 | **输入分层：HWND 消息 → CDP → UIA（执行后恢复）→ SendInput（需授权）** | 消息与 CDP 不抢焦点；UIA 动作会短暂激活窗口，由 FocusGuard 恢复 | 部分应用仍无法完全零激活输入 |
| 005 | **交互式托盘 daemon，不做 Windows 服务** | 服务看不到用户桌面 | 依赖登录自启；多用户需每会话一个 |
| 006 | **MCP + 本地 HTTP 双接口** | MCP 给 Agent，HTTP/WS 给状态页与其它语言客户端 | 两套接口需保持语义一致 |
| 007 | **v1 不打包 MSIX，接受离屏黄色捕获边框** | 边框在屏幕外，人看不到；避免打包复杂度 | 若窗口临时可见，边框可能闪一下 |
| 008 | **不自研 VDD，只支持用户自装并做检测** | 驱动签名/分发成本极高；避免安全与合规风险 | 保真兜底依赖用户环境 |
| 009 | **不做整屏捕获 API（默认）** | 与产品价值观冲突；减少隐私风险 | 状态页预览只能按 target 取图 |
| 010 | **元素引用 + 语义动作优先于纯坐标点击** | 滚动/动画下更稳；减少无效点击 | 需要维护 UIA/DOM 观测与 epoch |
| 011 | **Apache-2.0 + DCO，无 CLA** | 开源信任、降低贡献摩擦 | 无 |
| 012 | **单二进制 + 插件式后端接口** | 分发简单；社区可扩展 capture/input/observe | 需要维护稳定的接口 |
| 013 | **无遥测；诊断包 opt-in** | 隐私是产品的一部分 | 难以量化活跃用户 |
| 014 | **v1.0 UI = 托盘 + 极简状态页；完整 Dashboard 后置** | 维护成本低，先把核心做扎实 | 可视化能力有限 |

## 15. 失败模式矩阵

| 现象 | 可能原因 | 自动处理 | 上报 |
|---|---|---|---|
| 截图全黑 | 窗口最小化/隐藏/cloak；PrintWindow 不支持该应用 | 切 WGC（若可见/VDD）；仍失败 → degraded | `BLANK_FRAME` / `NOT_RENDERABLE` / `PROTECTED_CONTENT` |
| 截图与操作不符 | WGC 在离屏冻结；动画未停 | 改用 PrintWindow；延长 settle | `STALE_FRAME`（`stable:false`） |
| PrintWindow 卡住 | 目标应用无响应/绘制阻塞 | 超时并隔离 worker；不再重试该应用 | `CAPTURE_TIMEOUT` / `degraded` |
| 点击无反应 | Chromium 忽略消息；坐标错；元素已变 | 换 UIA/CDP；重新 observe | `INPUT_UNSUPPORTED` / `ELEMENT_STALE` / `likely_noop` |
| 窗口跑回屏幕 | 应用自我纠正位置 | 重停泊（退避） | 两次失败 → `PARK_UNSTABLE` |
| 抢了前台/光标动了 | UIA 动作激活了停泊窗口；或走了 SendInput | 优先 HWND 消息；UIA 执行后 FocusGuard 恢复；恢复失败报 `FOCUS_STOLEN` | `FOCUS_STOLEN` |
| UIA 动作被拒绝 | `strict_no_focus_steal=true`，或控件没有可执行 pattern | 关闭 strict；换坐标/消息动作；或换控件 | `FOCUS_STEAL_NOT_ALLOWED` / `ELEMENT_NOT_ACTIONABLE` |
| 提权窗口失败 | UIPI | 不重试 | `ELEVATED_TARGET` |
| 启动闪窗 | 首帧早于停泊 | 记帧数；优化启动序列 | 指标 `launch_flash_frames` |
| daemon 崩溃留下离屏窗口 | 未还原 | 下次启动按 `state.json` 恢复 | `RECOVERY_RESTORED` |
| 人手动最小化 target | 状态变化 | 停止捕获，等待恢复 | `TARGET_STATE_CHANGED` |
