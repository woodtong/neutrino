# 路线图与验收

> **定位更新（2026-10-22）：项目按开源项目推进，执行以 `07-开源项目规划.md` 为准。**
> 本文保留技术验收细节与测试矩阵；里程碑顺序/范围以 07 §11 为准（MCP 提前，Dashboard/VDD 后置，不做商业化）。
> 市场背景见 06：网页层已商品化，空位是"本地 + 原生 Windows + 隐形 + MCP"；微软 Agent Workspace 是最大威胁。

## 1. 长程执行方式

这是一个跨多个工作会话的项目。为了保证"长程不跑偏、质量不衰减"，采用下面的执行协议：

1. **垂直切片**：每个里程碑交付一个可演示的闭环（跑起来、能看到效果、有测试），而不是先铺框架。
2. **文档先行、边做边修**：开工前读 `02/03/07`；任何架构级偏离先改 ADR，再改代码。
3. **测试护栏**：M1 起建立回归套件；每个里程碑关闭前必须全绿（单元 + 集成 + 不变量）。
4. **兼容性矩阵**：每验证一个应用/后端组合，就更新矩阵；不靠记忆。
5. **进度日志**：每个会话结束在 `05-进度与决策日志.md` 追加：做了什么、证据（截图/日志/基准）、下一步、遗留问题。
6. **演示物**：每个里程碑留一个可复现的 demo（命令 + 截图/GIF + 预期输出）；没有演示物不算完成。
7. **风险前置**：M0 先验证最可能推翻架构的假设，避免"写完才发现路不通"。
8. **性能基线**：M1 起记录截图/点击延迟；M7 做一次完整基准，回归超过 30% 必须解释。

## 3. M0：可行性尖刀（必须先做）

**目标**：用最小代码验证 9 条关键假设（见 `01` §5），拿到数据，修订架构。**不做产品化**。

**做法**
- 一个 `spike/` 控制台项目（.NET 8，WinForms/WPF 仅用于测试窗口），实现：
  - 窗口枚举 + 停泊 + 还原；
  - WGC 取帧（含帧计数/时间戳/hash）；
  - PrintWindow 取图；
  - 状态快照（前台窗口、光标、剪贴板序列号）；
  - UIA 简单调用 + PostMessage 点击；
  - 无头 Edge 启动 + CDP 截图/DOM 查询；
  - 主显示器 DXGI 复制（用于"不可见"验证）。
- 用 Notepad、Explorer、Edge（GUI）、VS Code（若安装）做样本。

**通过标准**
- H1：离屏窗口连续 20 帧中 ≥ 18 帧 hash 变化（有动画时），且 `last_frame_at` 持续更新；若为 0 变化 → 记录失败。
- H2：PrintWindow 对每个样本至少一个状态可用；空白/纯色比例有统计。
- H3：停泊/截图/还原前后，前台 hwnd、光标坐标、剪贴板序列号完全一致。
- H4：离屏 Edge 的 CSS 动画帧持续变化；关闭/开启禁节流参数各测一次。
- H5：Notepad/Explorer 的按钮 Invoke、输入框 SetValue 成功，且前台窗口不变。
- H6：Fixture/Notepad 的 PostMessage 点击/输入成功。
- H7：无头 Edge 打开本地页，截图/DOM/点击/console 全部成功，连续 100 次无泄漏。
- H8：至少在一台 150% 缩放显示器上，图像坐标 → 元素命中正确（用 UIA bounds 对照）。
- H9：枚举显示器并识别是否存在 VDD（有则测，没有则标记 N/A）。

**产出**
- `spike/REPORT.md`：每条假设的结论、证据路径、对架构的影响。
- 更新 `01` 的置信度、`02` 的 ADR。
- 明确 Plan B 是否启用。

**风险**：若 H1 失败且 H4 也失败，通用路径需要 VDD，产品形态从"零依赖"变成"需装驱动"——必须在 M0 后与用户重新确认优先级。

## 4. M1：捕获内核

**范围**
- 解决方案骨架：`Core/Windows/Capture/Cli` + 测试项目 + `FixtureApp`。
- 窗口枚举与识别（hwnd、pid、title、class、cloak、DPI、显示器）。
- ParkingManager：保存/停泊/校验/还原/watch；启动流程（SW_HIDE → 停泊 → 显示）。
- PrintWindow 后端（离屏主路径）：强制绘制、客户区裁剪、空白/超时检测。
- WGC 后端（可见/VDD）：D3D11、帧池、尺寸变化、超时、取消；帧 hash。
- CaptureEngine：选择、降级、稳定性等待、缩放、PNG 编码、元数据。
- CLI：`gs list/open/shot/close`（先直连，不做 daemon）。
- 不变量测试：前台/光标/剪贴板；窗口不在任何显示器内。
- 基准：1280×800 截图 p50/p95。

**验收**
- [ ] 记事本离屏截图能看清文字（视觉验收）。
- [ ] Edge GUI / VS Code 至少一个通过 CDP 或 PrintWindow 拿到实时画面；失败项写入兼容矩阵。
- [ ] 最小化/隐藏窗口返回 `NOT_RENDERABLE`，不返回黑图。
- [ ] `gs shot` 输出 PNG + JSON 元数据；连续 100 次无泄漏。
- [ ] 还原后窗口位置/大小/状态与原来一致（逐字段比对）。
- [ ] 停泊全程前台/光标/剪贴板不变（自动化断言）。
- [ ] 性能达到 p50 ≤ 200ms（M1 阶段目标，M7 收紧；P0 PrintWindow 已 ≈12ms）。

## 14. 项目级验收场景

1. **前端视觉验证**：Agent 在 3 个视口截图、发现 console 错误、修复后复验；全程无窗口出现、无焦点变化。
2. **桌面文本录入**：Agent 在记事本输入中英文并截图确认；前台/光标/剪贴板不变。
3. **多 Agent 并行**：3 个 target 同时工作 10 分钟；人的前台窗口保持不变；无句柄/内存泄漏。
4. **降级诚实**：对 Chromium 窗口尝试像素消息点击 → 返回 `INPUT_UNSUPPORTED` 与建议，而不是假装成功。
5. **灾难恢复**：强制杀 daemon → 重启 → 所有离屏窗口被还原；急停 1s 内生效。
