# 市场与需求调研

> 调研日期：2026-10-22。对象：**本地 Windows 11 上，让 Agent 隐形使用原生应用窗口（离屏停泊 + 捕获 + 隔离输入）+ MCP** 的产品方向。
>
> **定位更新（2026-10-22）**：项目已确定为**开源项目**，不追求商业化。本文的商业模型、TAM/SAM/SOM 与定价仅作背景和风险评估，**不作为目标**；开源执行规划见 `07-开源项目规划.md`。
>
> **一句话结论：有同类，但没有完全同类的本地产品；网页层已经是红海，原生 Windows 的"隐形层"仍是空位；需求真实但窄；收益是"小而美"，不是大风口。建议缩小 MVP、先验证、把 CI 无头 Windows 测试作为第二楔子。**

## 0. 先给判断

| 问题 | 结论 |
|---|---|
| 有没有同类型产品？ | 有大量相邻产品，但"本地 + Windows 原生应用 + 对人不可见 + MCP + 多 Agent"这个组合，截至 2026-10 没有发现成熟产品。 |
| 有没有需求？ | 有，且被微软自己（Agent Workspace）和 UiPath（PiP）验证过；但主要是"隔离/不打扰"的需求，不是"隐形屏幕"这个具体功能的需求。 |
| 网页部分值得做吗？ | **不值得作为卖点**。无头浏览器、Playwright MCP（38.5k stars）、Chrome DevTools MCP（54k stars）、云端浏览器把这块打成了免费/低价基础设施。 |
| 真正的空位在哪？ | **原生 Windows 应用的本地隐形执行层**：不装驱动、不上云、不占第二块屏、不抢焦点，通过 MCP 给任意 Agent 用。 |
| 最大威胁？ | **微软 Windows 11 Agent Workspace**：本机独立账户 + 独立桌面，和我们的核心价值高度重叠；目前是实验性，第三方 API 私测。时间窗约 12–24 个月。 |
| 能赚多少钱？ | 作为独立产品：基准情形 3 年约 **$1–1.5M ARR**，保守 $0.3M，乐观 $5M；TAM 约 **$0.3–0.5B**。不是风投级，但是可行的小团队/独立产品。 |
| 最稳的付费楔子？ | **CI 里的无头/并行 Windows GUI 测试**：WinAppDriver 已死、Appium 单会话、RDP/tscon 土办法横行，付费意愿比个人开发者高。 |
| 如果只是自己用？ | 值得做。网页需求先用现成的 headless 工具；原生应用自动化才是这个项目对你个人的真正价值。 |

- 微软 2025-10-16 博客：Agent Workspace、Agent Accounts、Copilot Actions 的定位与实验状态。
- Microsoft Learn：Windows 365 for Agents 是云端 Cloud PC，check-out/check-in 模式，Intune 管理。
- 阿里云 AgentBay：云端 Windows/Linux 桌面、MCP、点数计费、已可自助开通。
- UiPath PiP 文档：同机独立 Windows 会话、一次一个、显示 PiP 预览窗、剪贴板共享、企业限制。
- GitHub stars：Playwright MCP 38,509；Chrome DevTools MCP 53,982；Windows-MCP 9,977；Terminator 1,657；UI-TARS Desktop 39,367；browser-use 118,856；Cua 30,654。
- Browserbase 定价：Free / $20 / $99，超量 $0.10–0.12/browser-hour。

**方向性证据（二手/未能逐条打开验证）**
- 市场规模数字来自 Grand View Research、MarketsandMarkets、Gartner 等公开摘要，口径差异大。
- 社区痛点（GitHub issue、HN/Reddit 讨论）来自搜索摘要，部分链接在本次调研中超时未打开；只作为方向性证据，不作为精确引用。
- 微软 Agent Workspace 的 GA 时间：官方最新可核实状态仍是实验性；二级报道称随 26H2 推进，**官方未确认日期**。

**本文的 TAM/SAM/SOM 是我们自己的自下而上估算**，不是第三方结论；所有假设在附录列出。

## 2. 市场分层：谁在解决什么问题

这个市场不是"一个赛道"，而是五层相邻能力：

```
┌─ 平台原生隔离 ──────────────────────────────────────────────┐
│ Microsoft Agent Workspace / Agent Accounts（本机独立会话）  │
│ 目前实验性，第三方 API 私测                                  │
└─────────────────────────────────────────────────────────────┘
┌─ 云端 Agent 桌面 / 沙箱 ────────────────────────────────────┐
│ Windows 365 for Agents, AgentBay, Daytona, E2B, Cua Spaces  │
│ 给 Agent 一台机器；天然隐形；按小时/按月计费                 │
└─────────────────────────────────────────────────────────────┘
┌─ 无头浏览器基础设施 ────────────────────────────────────────┐
│ Browserbase, Steel, Anchor, Hyperbrowser, Browserless,      │
│ Kernel, Browser Use Cloud, AWS AgentCore Browser            │
│ 只解决 Web；便宜、成熟、红海                                 │
└─────────────────────────────────────────────────────────────┘
┌─ 本地 Windows 自动化 ───────────────────────────────────────┐
│ UiPath, Power Automate, Windows-MCP, Terminator, UI-TARS,   │
│ pywinauto, FlaUI, Appium Windows Driver                     │
│ 操作真实可见桌面；UIA/像素/输入注入                           │
└─────────────────────────────────────────────────────────────┘
┌─ 虚拟显示器 / 远控 ─────────────────────────────────────────┐
│ Parsec VDD, MTT Virtual-Display-Driver, usbmmidd, Sunshine  │
│ 是管道，不是产品；可作为保真兜底                              │
└─────────────────────────────────────────────────────────────┘
```

**关键洞察**：
- 云端方案解决"隐形"，但代价是钱、延迟、数据出本地、拿不到本地已登录的软件/文件。
- 本地方案解决"本地"，但几乎都操作**可见桌面**，会抢焦点/光标，无法并行。
- 平台原生（Agent Workspace）同时解决本地 + 隐形，但它是微软生态、实验性、第三方不可控。
- **"本地 + 原生 + 隐形 + 厂商中立 + MCP"没人占住**——这是 GhostScreen 的位置。

## 4. 最接近的六个替代品

### 4.1 Microsoft Agent Workspace（最大威胁，也是最大验证）

- 官方（2025-10-16）：Agent 使用**独立标准账户**，在**自己的桌面/会话**里工作，"like its own desktop"，与用户并行；默认关闭，需管理员开启；第三方开发者平台能力"private preview soon"。
- 它几乎就是我们想做的：本地、独立桌面、人看不到、原生应用。
- 但：实验性、微软生态/Entra/Intune 导向、第三方 Agent 接入受控、无公开 MCP 开发面；企业部署复杂。
- **时间窗**：如果 12–24 个月内它开放稳定的第三方 API + MCP，我们的核心价值会被大幅商品化。反过来，如果它继续封闭/实验，我们有机会成为"厂商中立的本地执行层"。

### 4.2 UiPath Picture-in-Picture（最接近的商业产品）

- 同一台机器、独立 Windows 会话，人在主会话继续工作；机器人可以跑原生应用。
- 但：会显示 PiP 预览窗口（不是完全隐形）、**一次只能一个会话**、剪贴板共享、企业定价、面向工作流而非 Agent/MCP。
- 它证明"人机并行"的企业付费意愿；也说明"完全隐形 + 多会话"仍是空白。

### 4.3 Cua（概念最接近的开源产品）

- 本地 "Spaces"、MCP、多 Agent、开源，30.7k stars。
- 但宿主是 **Apple silicon Mac（macOS 26+）/ Linux Docker**；Windows 只是"被控目标"，不是"Windows 本机隐形桌面"。
- 它验证了"Agent 需要自己的桌面空间"和"MCP + 多 Agent"的产品形态。

### 4.4 Windows-MCP / Terminator / UI-TARS（需求证明）

- 本地、原生、免费/开源，10k–39k stars，说明开发者确实想让 Agent 操作 Windows。
- 但都操作**可见桌面**；UIA 能不碰光标，却不能不让窗口出现；并行会互相抢焦点。
- 它们最容易被我们的"停泊 + 隔离"能力增强，甚至可以作为上游/下游集成对象。

### 4.5 Playwright MCP / Chrome DevTools MCP（Web 层替代）

- 免费、成熟、star 数最高（38.5k / 54k），支持 headless。
- 直接满足"前端截图不弹窗"的需求；**我们不应该在这里竞争**。
- 但它们是浏览器专用，碰不到原生应用、桌面客户端、本地文件。

### 4.6 云端 Windows（W365 for Agents / AgentBay / Daytona）

- 真正"隐形 + 原生 Windows"，但按小时/按月付费、数据出本地、需要网络/IT、拿不到本地授权软件和登录态。
- 对企业的合规场景有吸引力；对个人开发者/隐私敏感场景，本地工具更便宜、更直接。

## 5. 需求证据

### 5.1 分场景评分

| 场景 | 痛点强度 | 现有替代 | 付费意愿 | 竞争 | 判断 |
|---|---|---|---|---|---|
| 前端视觉验证（Web） | 中高 | 强且免费（headless/Playwright MCP） | 低 | 红海 | **功能，不是卖点** |
| 原生 Windows 应用的 Agent 自动化 | 高 | 弱/贵（VM、PiP、云桌面） | 中 | 低 | **核心楔子** |
| CI 无头/并行 Windows UI 测试 | 高 | 差（WinAppDriver 死、RDP/tscon 土办法） | 高 | 低 | **最佳商业楔子** |
| 个人多 Agent 并行 | 中 | 无 | 低–中 | 低 | 开源增长点 |
| 隐私敏感的本机自动化（金融/医疗/内部工具） | 高 | 只有云 | 高 | 低 | 企业后期 |
| 通用 RPA | 高 | 强（UiPath/Power Automate/国产 RPA） | 高 | 高 | **不要正面竞争** |

### 5.2 支持需求的信号

1. **微软亲自下场**：Agent Workspace / Agent Accounts 的存在，说明"Agent 需要与人隔离的桌面"被平台方认定为真问题。这是最强的需求验证。
2. **UiPath 做了 PiP**：企业客户愿意为"机器人跑着，我还能用电脑"付费；但 PiP 一次一个、有预览窗、贵。
3. **本地 Windows Agent 工具的 star 数**：Windows-MCP 10k、UI-TARS 39k、Terminator 1.7k；说明开发者想让 Agent 操作 Windows，只是现有工具会占桌面。
4. **浏览器 MCP 的 star 数**：Playwright MCP 38.5k、Chrome DevTools MCP 54k；说明"Agent + 浏览器自动化"已经是主流工作流。
5. **云 Agent 沙箱的融资/产品**：Browserbase 等公司获得大额融资（公开报道），E2B、Daytona、AgentBay、W365 for Agents 持续推出产品；说明"隔离执行环境"有预算。
6. **CI 的 Windows GUI 测试痛点**：WinAppDriver 2020 年后停更、官方 issue 长期讨论"锁屏/RDP 断开后 UI 测试失败"；社区用自动登录 + `tscon` + 鼠标抖动 + 虚拟显示器等土办法。没有现代、并行、无头的方案。
7. **AI 编码工具的收入规模**：Cursor、Claude Code 均达到 $1B ARR 级别（公开报道），证明开发者愿意为提效工具付费。

### 5.3 反面证据（必须正视）

- **没有找到"我愿意为隐形 Windows 窗口付钱"的直接帖子/定价页**；需求是从"隔离/不打扰"推断的。
- 很多开发者用免费 UIA/headless 工具就能凑合；"隐形"是体验升级，不一定是预算项。
- Web 视觉验证已被免费方案覆盖；如果产品叙事停留在"截图不弹窗"，会被认为"我用 Playwright 就行"。
- 原生应用自动化的兼容性长尾很长，用户预期却很高；支持成本可能吃掉利润。
- 微软 Agent Workspace 一旦 GA 并开放，独立产品的核心卖点会被大幅削弱。

## 6. 市场规模与受众

### 6.1 Top-down 参考（第三方估算，口径不一）

|---|---|---|
| RPA | $4.7B（2025）→ $35.8B（2033），29.0% CAGR | Grand View Research |
| 自动化测试 | $55.2B（2028），14.5% CAGR | MarketsandMarkets |

### 6.2 自下而上 TAM / SAM / SOM（我们的估算）

**假设链**
1. 专业开发者 36.5M × Windows 主力 49.5% ≈ **18.1M Windows 专业开发者**。
2. 其中经常运行 GUI 类 Agent 工作流（前端验证、桌面自动化、Windows UI 测试）的比例：**10–15%** → **1.8–2.7M 人**。
3. 可接受年费：**$120–180/人/年**（$10–15/月，参考 Browserbase $20、Cua $15、W365 $36+）。
4. MCP 生态可触达人群：约 **100–300k** 活跃 MCP Agent 用户（由 Playwright MCP 38.5k + DevTools MCP 54k + Windows-MCP 10k 的 star 数粗估，star ≠ 用户）。
5. 其中 Windows 且感受到"窗口/焦点"痛点的比例：**30–50%**。
6. SAM 年费同上。

**结果**

| 层 | 估算 | 说明 |
|---|---|---|
| **TAM** | **$0.22–0.49B/年** | 1.8–2.7M GUI 工作流用户 × $120–180 |
| **SAM** | **$8–20M/年** | 100–300k MCP 用户 × 30–50% Windows × $120–180，取中位 |
| **SOM（3 年）** | **$0.3–5M/年** | 见下表 |

**SOM 三情景**

| 情景 | 第 1 年 | 第 3 年 | 假设 |
|---|---|---|---|
| 保守 | ~$46K | ~$0.32M | 400 → 2,500 付费个人 + 60 个小团队 |
| 基准 | ~$170K | ~$1.4M | 1,200 → 8,000 付费个人 + 250 个团队/CI |
| 乐观 | ~$540K | ~$5M | 3,000 → 20,000 付费个人 + 600 个团队/CI |

> 这些是**规划用数量级**，不是预测。个人订阅是"量"的生意；团队/CI 是"单价"的生意，后者决定上限。

### 6.3 谁最可能付费

1. **AI 编码重度用户 / 独立开发者**：$10–15/月，愿意为"不打断我"付费；但价格敏感、替代品多。
2. **QA/测试团队**：需要并行、无头、稳定的 Windows UI 测试；预算参照 BrowserStack/Applitools/VM，单价高。
3. **RPA/自动化团队**：想摆脱"每个机器人一台 VM"；但已有 UiPath/Power Automate，替换成本高。
4. **隐私敏感行业**（金融、医疗、法务、内部工具）：不能把屏幕/数据送到云；本地执行是刚需，客单价高。
5. **Agent 平台厂商**：想把"本地 Windows 执行"作为能力嵌入自己的产品；B2B SDK/授权，可能是最大的单笔收入，但销售周期长。

## 7. 收益模型

### 7.1 自用收益（如果只为自己）

- **时间**：每次视觉验证省 30–60 秒的切窗/找窗/恢复；一天 20 次 ≈ 10–20 分钟；多 Agent 并行时收益更大。
- **硬件**：不需要第二块屏（$150–500）或云 VM（$36–150/月）。
- **体验**：不被打断的深度工作；这是最难量化但最真实的价值。
- **能力**：可以跑"人机并行"的自动化（ Agent 跑 GUI 任务，你继续写代码）。
- **结论**：即使不商业化，作为个人工具也值得做。

### 7.2 开源收益

- 声誉、社区、招聘/咨询机会；MCP 生态的曝光。
- 赞助（GitHub Sponsors/Open Collective）通常很小（$100–2,000/月），不能当主业。
- 可以通过"开源核心 + 付费 Pro/Team"转化。

### 7.3 商业模型（建议）

| 层级 | 价格（建议） | 包含 | 目标 |
|---|---|---|---|
| **Free / OSS** | $0 | 1 个 target、核心捕获/输入、MCP、CLI | 获客、标准化 |
| **Pro** | $12/月 或 $99/年 | 8 个 target、Dashboard、会话日志、应用配置、优先更新 | 个人开发者 |
| **Team** | $99/月（5 席）或 $15/席/月 | 共享策略、审计导出、团队 target 池、CI runner | 小团队 |
| **CI / Enterprise** | $1–2K/年起/并发 runner；企业定制 | 无头/并行 Windows UI 测试、Appium 兼容、SSO、支持 | QA/企业 |
| **OEM / SDK** | 定制 | 把本地 Windows 执行层嵌入 Agent 平台 | 平台厂商 |

**盈亏平衡（粗算）**
- 单人全职成本按 $60–100K/年计；$12/月产品需要 **~420–700 个付费订阅**，或 **50–80 个 Team 客户**，或 **10–20 个 CI/企业客户**。
- 若作为副业/开源项目，成本主要是时间，盈亏平衡点低得多。

### 7.4 成本结构

- **MVP**：25–33 人日（见 `04-路线图与验收.md`）；市场验证再加 5–10 人日。
- **维护**：兼容性矩阵是长期成本；Windows 更新、应用改版、驱动/API 变化；建议预留 20–30% 开发时间。
- **支持**：每个应用家族的问题都可能变成支持工单；这是最大的隐性成本。
- **签名/分发**：代码签名证书 $200–500/年；若做安装器/MSIX 还有打包与测试成本。
- **基础设施**：几乎为零（本地工具，无云）；网站/文档 ~$20/月。
- **营销**：主要靠内容/开源/HN/Product Hunt/MCP 目录，现金成本低，时间成本高。

### 7.5 战略收益

- 成为"本地 Windows 执行层"的标准/MCP 基础设施，可能被 Agent 平台、RPA、测试厂商集成或收购。
- 即使不卖，代码与文档也是高质量的 portfolio，能带来机会。
- **不要把"被收购"当商业计划**；它只是可选结果。

## 8. 护城河、威胁与时间窗

### 8.1 护城河（真实但不高）

- **兼容性矩阵**：哪些应用能停泊、能捕获、能 UIA/消息输入——这是时间和经验堆出来的。
- **输入隔离的 UX**：UIA/CDP/消息的自动选择、坐标映射、失败降级、settle 策略。
- **多 Agent 并行与恢复**：崩溃恢复、状态持久化、急停、审计。
- **厂商中立 + MCP**：不和某一家 Agent 绑定。
- **信任**：本地、开源、可审计、无遥测。

**不是护城河**：WGC/PrintWindow 本身是公开 API；一个熟练开发者几周就能做出 demo。真正的壁垒是"稳定覆盖一堆真实应用"。

### 8.2 威胁

| 威胁 | 概率 | 影响 | 说明 |
|---|---|---|---|
| **微软 Agent Workspace GA + 开放第三方 API/MCP** | 中高 | 高 | 核心价值被平台吸收；时间窗 12–24 个月（不确定） |
| 云 Windows 变便宜（W365/AgentBay/Daytona） | 高 | 中 | 企业更愿意买云；本地只剩隐私/成本/离线场景 |
| 无头浏览器继续商品化 | 已发生 | 高（对 Web 卖点） | Web 层没有差异化 |
| 开源克隆 | 高 | 中 | API 公开，demo 易复制；靠兼容性与体验取胜 |
| 安全事件（Agent 误操作/提示注入） | 中 | 高 | 一次事故会打击信任；需要权限/审计/急停 |
| 兼容性长尾拖垮维护 | 高 | 中 | 必须明确"支持矩阵"，不承诺全能 |
| Windows 家庭版限制（本机） | 中 | 低 | 我们无驱动/无 Hyper-V，反而适配 Home |

### 8.3 时间窗判断

- **0–12 个月**：Agent Workspace 仍是实验性/私测；云端 Windows 在商品化但贵；本地隐形层空位明确。**最佳切入期。**
- **12–24 个月**：微软可能开放 Agent Workspace API；云价格继续下降。需要在此之前建立用户/兼容性/社区壁垒，或转向 CI/企业。
- **24 个月+**：如果平台原生能力成熟，独立产品需要转型为"跨平台编排层/兼容层/企业治理层"。

## 9. 定位与执行建议

### 9.1 推荐定位

> **GhostScreen：Windows 上给 Computer-Use Agent 的本地执行层。**
> 让 Agent 在不打扰人的前提下，真实地看和操作原生应用；通过 MCP 接入任意 Agent；网页是内置能力，不是卖点。

一句话电梯陈述：
> "Playwright 让 Agent 用浏览器；GhostScreen 让 Agent 用你的 Windows 应用——但不占你的屏幕、不抢你的鼠标。"

### 9.2 两个楔子

1. **开发者楔子（MVP）**：AI 编码/自动化重度用户，需要原生应用 + 浏览器，不想被窗口打断。开源 + Pro 订阅。
2. **CI 楔子（收入）**：QA 团队需要并行、无头、稳定的 Windows GUI 测试。Team/CI 授权，客单价更高。
   - 这一层需要额外的 Appium/WinAppDriver 兼容、测试隔离、并行调度；不要在 MVP 阶段做，但架构上预留（target 池、并发、确定性截图、日志）。

### 9.3 MVP 范围（建议 6–8 周）

- **做**：
  - 窗口枚举 + 停泊 + 还原 + watch；
  - WGC 截图 + PrintWindow 兜底 + 稳定性/空白/过期检测；
  - UIA 观测 + 语义动作 + 消息输入；
  - 无头 Edge + CDP（截图/DOM/点击/console）；
  - MCP 服务器（`open/screenshot/observe/click/type/close`）+ CLI；
  - 多 target（4–8 个）+ 崩溃恢复。
- **不做（至少第一版）**：
  - 自研 VDD/驱动；
  - 大而全的 Dashboard/托盘（先 CLI + MCP，等设计伙伴反馈）；
  - 安装器/自动更新；
  - 企业 SSO/审计导出；
  - 跨平台。
- **验收**：3 个真实场景（前端三视口验证、记事本中文输入、两个 Agent 并行）+ 不变量测试（前台/光标/剪贴板/不可见）。

### 9.4 验证计划（与开发并行）

- **10–15 个访谈**：AI 编码重度用户、QA 负责人、RPA 顾问；问"上次 Agent 弹窗打断你是什么时候/你怎么解决的/愿意付多少"。
- **90 秒 demo**：屏幕左边人正常打字，右边 Agent 在"看不见的窗口"里截图/点击；最后切到 Dashboard 展示。
- **Landing page + waitlist**：明确"本地、无云、MCP、Windows 原生"。
- **分发**：MCP 目录（Glama/Smithery 等）、GitHub、HN Show HN、Reddit r/ClaudeAI / r/LocalLLaMA / r/QualityAssurance、中文社区。
- **指标**：waitlist 转化、7 日留存、每周使用次数、最常请求的应用、付费意向。
- **Kill / pivot 条件**（写死，避免自我欺骗）：
  1. M0 的 H1（离屏 WGC）失败，且 VDD 方案在 2 周内无法稳定 → 缩到"受控应用 + CDP"，或停。
  2. 微软在 12 个月内开放稳定的 Agent Workspace + MCP → 转做其插件/跨平台编排，或停。
  3. 10 个设计伙伴中 <3 个在 6 周后仍每周使用 → 需求不成立，停或转。
  4. 兼容性支持 > 1 人日/周/10 个用户 → 收窄支持矩阵。

### 9.5 分阶段目标（如果做成产品）

| 阶段 | 时间 | 目标 |
|---|---|---|
| 验证 | 0–1 月 | M0 + 10–15 访谈 + demo + waitlist |
| MVP | 1–3 月 | 20 个设计伙伴；5 个每周活跃；2 个付费意向 |
| 公测 | 4–6 月 | 1,000 安装；50 周活；10 个付费；$1–2K MRR |
| 商业化 | 7–12 月 | Team/CI 楔子；$5–15K MRR；或明确 pivot |
| 扩展 | 12–24 月 | $0.3–1.5M ARR；企业/ OEM 合作；或并入平台生态 |

## 10. 最终判断

**做，但要换一个做法。**

- **不要**把它当成"隐形屏幕"这个单点功能去卖；会被无头浏览器和微软 Agent Workspace 夹击。
- **要**把它做成"本地 Windows 的 Agent 执行层"：原生应用 + 隐形 + 隔离输入 + MCP + 多 Agent，这是 2026-10 仍然空着的位置。
- **优先级**：原生 Windows > 多 Agent 并行 > MCP 生态 > 网页（网页必须有，但不是壁垒）。
- **商业上**：先做开源/个人开发者，验证留存；有信号后再做 Team/CI（更高的付费意愿）；不要一开始就做企业功能。
- **风险上**：给自己 12–24 个月窗口；把"微软开放 Agent Workspace"作为明确的 pivot 触发条件，而不是意外。
- **如果只为自己用**：直接做，收益是每天的时间和不被打断的注意力；网页部分先用现成 headless 工具，别重复造轮子。
