# 开源项目规划（v1.0）

> 定位变更（2026-10-22）：项目按**开源项目**推进，不按商业产品设计。
> 评价标准从 "ARR/市场" 改为：**陌生人能否在 5 分钟内安全用起来；工程质量能否长期维护；是否真的不打扰人。**
>
> 本文是开源执行的主文档。`04-路线图与验收.md` 中的技术里程碑仍可参考，但范围、优先级、发布标准以本文为准。

## 0. 一句话与边界

**GhostScreen：给 Windows 上的 Computer-Use Agent 一块人看不见的屏幕。**

- 本地运行，不上云；原生应用真实渲染，但窗口停在所有显示器之外。
- Agent 通过 MCP 截图、观察、点击、输入；人继续用自己的电脑。
- 开源（Apache-2.0），无遥测、无付费墙、无账号体系。
- 支持范围明确、失败时说人话；不假装支持所有应用。

**不是什么**
- 不是 RPA 平台、不是远程桌面、不是云桌面、不是游戏串流。
- 不注入目标进程、不做 DLL Hook、不绕过受保护内容。
- 不自研内核驱动；虚拟显示器只做"检测用户已装驱动 + 适配"。
- v1 不支持 macOS/Linux；不承诺 Windows 10（以 Win11 22H2+ 为准）。

**名字**：`GhostScreen` 是工作名。发布前做 GitHub/商标/包名检索；如有冲突，备选 `GhostFrame`。不要把命名拖到发布前一周。

## 1. 为什么开源，以及开源改变了什么

### 1.1 为什么开源

1. **它要看你的屏幕、动你的应用**。闭源工具很难获得信任；开源 + 本地 + 可审计是产品的一部分。
2. **兼容性长尾靠社区**。"哪个应用能停泊、哪个不能、哪个要 CDP"这种矩阵，只有真实用户能补齐。
3. **MCP 生态靠分发**。开源 MCP server 更容易被 Claude Code、Codex、Cursor、ZCode 等客户端收录和试用。
4. **没有云成本**。维护者不需要为每个用户付服务器钱，项目可以长期存在。
5. **不追求增长**。没有融资/营收压力，可以拒绝不合理的范围。

### 1.2 开源带来的约束

- **不能靠"以后收费"兜底**：第一版就要有完整可用的核心，不做"试用版"。
- **文档是产品的一部分**：没有 5 分钟 Quick Start，等于没做。
- **兼容性必须诚实**：支持/部分支持/不支持，写清楚；不把黑图当成功。
- **维护成本要克制**：不做大而全；v1 只把 6–8 个应用做扎实。
- **治理要轻**：Apache-2.0 + DCO，不要 CLA、不要基金会、不要复杂的 RFC 流程。

## 2. 质量定义："不能太次"的 10 条红线

| # | 维度 | v0.1 及格线 | v1.0 优秀线 |
|---|---|---|---|
| 1 | **正确性** | 3 个应用截图正确；坐标点击命中 | 6–8 个应用；黄金图对比；坐标/DPI 回归测试 |
| 2 | **不打扰** | 停泊/截图不抢前台、不动光标、不碰剪贴板 | 全流程自动化断言 + 不可见性逐帧验证 |
| 3 | **可靠性** | 错误码 + 可关闭；不崩溃 | 崩溃恢复；24h soak；无孤儿窗口/进程；急停 |
| 4 | **性能** | 1280×800 截图 p50 < 300ms | p50 < 150ms；基准入仓；回归 >30% 需解释 |
| 5 | **兼容性** | 支持矩阵有 3 个应用 | 8 个应用 + 每个都有 recipe/已知限制 |
| 6 | **安全** | 仅回环 + token；急停 | 威胁模型、审计、SECURITY.md、无遥测、提权边界 |
| 7 | **开发者体验** | CLI 可用；错误能看懂 | `gs doctor`、5 分钟 Quick Start、MCP 配置示例、诊断包 |
| 8 | **代码质量** | 能构建、有单测 | nullable、分析器、warnings-as-errors、分层清晰、无 P1 |
| 9 | **文档** | README + 限制说明 | 架构/API/recipes/troubleshooting/对比/基准 + 90 秒 demo |
| 10 | **分发** | GitHub Release zip + SHA256 | 签名（或明确说明）、winget/scoop、SBOM、变更日志 |

### 2.1 明确拒绝的"业余感"

- ❌ 把全黑/纯色截图当成功返回。
- ❌ 为了截图/输入把窗口弹到人眼前，或移动真实光标。
- ❌ README 写"支持所有 Windows 应用"。
- ❌ 没有测试、没有校验和、没有变更日志就发版。
- ❌ 退出/崩溃后留下离屏窗口或孤儿进程。
- ❌ 错误只抛 `Exception` / "failed"，没有 code、hint、文档链接。
- ❌ 默认收集遥测/上传截图。
- ❌ 用"未来会支持"掩盖当前不支持。

### 2.2 发布闸门（每个版本都要过）

- [ ] CI 全绿：build + 单测 + 分析器 + CodeQL + dependency review。
- [ ] 集成测试在交互式会话跑过（本地或 self-hosted runner），证据入 issue/release。
- [ ] 不变量测试通过：前台窗口、光标、剪贴板、窗口不在任何显示器内。
- [ ] 基准在基线 ±30% 内；无句柄/内存持续增长。
- [ ] 兼容矩阵更新；新增"部分支持/不支持"要写原因。
- [ ] 文档更新：README、Quick Start、API、Troubleshooting、CHANGELOG。
- [ ] 没有 P0/P1；已知问题有 issue 链接。
- [ ] 产物有 SHA256；有 SBOM；能签名就签名。
- [ ] 在干净机器/新用户配置下按 Quick Start 走一遍。

## 3. 范围（MoSCoW）

### Must（v0.1 / v1.0 必须有）

- Windows 11 22H2+（build 22621+），x64；.NET 8 self-contained。
- 窗口枚举、停泊（离屏）、还原、watch；不抢焦点。
- PrintWindow 作为离屏主捕获；WGC 用于可见/VDD；空白/过期/稳定性检测。
- UIA 观测 + 语义动作；窗口消息输入；坐标映射（image/client/screen）。
- 无头 Edge + CDP：截图、DOM 观测、点击/输入、console/network。
- MCP stdio 服务器（6–8 个核心工具）+ CLI；多 target（4–8）。
- `gs doctor`、结构化日志、错误码、急停。
- 5 个应用验证：FixtureApp、记事本、文件资源管理器、无头 Edge、VS Code（CDP）。
- 文档：README（含 demo）、Quick Start、MCP 配置、限制、Troubleshooting。
- Apache-2.0、CONTRIBUTING、CODE_OF_CONDUCT、SECURITY、issue/PR 模板。

### Should（v0.5 / v1.0）

- 托盘 + 极简状态页（不是完整 Dashboard）：target 列表、最近截图、急停。
- 多显示器/混合 DPI；锁屏/唤醒/虚拟桌面切换后的恢复或明确报错。
- 崩溃恢复（state.json + 启动还原）。
- 8 个应用矩阵；recipes（Edge/Chrome/VS Code/Notepad/Explorer）。
- 基准套件；24h soak。
- winget + Scoop 清单；安装脚本；代码签名（SignPath OSS 或明确未签名）。
- 网页多视口快照 `gs web snapshot`（便捷层）。

### Could（v1.x，不阻塞 v1.0）

- BYO 虚拟显示器（Parry/MTT VDD）检测与停泊。
- 提权模式（显式）。
- 插件 SDK（自定义 capture/input backend）。
- 会话录制/回放（截图序列）。
- 中文/英文 UI 与文档完整双语。
- 完整 Dashboard（实时预览、时间线、审计浏览）。
- ARM64 支持。

### Won't（明确不做）

- 自研 IddCx 驱动/驱动分发。
- 云服务、账号、遥测、付费墙。
- RPA 工作流编辑器、录制器。
- 游戏/独占全屏/DRM/受保护内容。
- 跨平台。
- 对"所有应用"的兼容承诺。

## 4. 架构调整（为开源与可维护性）

### 4.1 进程与二进制

- **一个 `gs.exe`** 包含子命令：
  - `gs daemon`：启动守护进程（托盘可选）。
  - `gs mcp`：stdio MCP 桥。
  - `gs doctor` / `gs doctor --bundle`：环境诊断（诊断包脱敏）。
  - `gs open/shot/click/type/close/panic`：CLI。
  - `gs ui`：打开极简本地状态页。
  - `gs --tray`：托盘模式。
- 减少分发复杂度：用户只下载一个 zip；不要求装 .NET。
- 托盘用 WinForms `NotifyIcon`（简单可靠）；状态页用静态 HTML + 原生 JS（不引入 React 构建链，v1.0 不做完整 Dashboard）。

### 4.2 分层与可测试性

```
GhostScreen.Core        纯逻辑：Target、状态机、坐标、稳定性、错误、配置
GhostScreen.Windows     Win32/WinRT/UIA：窗口、停泊、DPI、UIA、输入
GhostScreen.Capture     ICaptureBackend: PrintWindow / WGC / (VDD) / CDP
GhostScreen.Input       IInputStrategy: UIA / CDP / Message / SendInput
GhostScreen.Web         Edge 生命周期 + 最小 CDP 客户端
GhostScreen.Daemon      Kestrel + WS + 命名管道 + 审计 + 恢复
GhostScreen.Mcp         MCP 工具定义 + stdio
GhostScreen.Cli         子命令、doctor、ui、tray
```

**硬规则**
- `Core` 不引用 `Windows`；坐标/稳定性/选择策略可在无 GUI 环境单测。
- 每个 backend 实现同一个接口，新增应用族/捕获方式不改核心。
- Win32 互操作集中在 `Windows`，用 `SafeHandle`，禁止散落 P/Invoke。
- 所有异步操作可取消；target 操作串行化，避免"边点边截"。
- 配置有 JSON Schema；`gs doctor` 校验。

### 4.3 依赖政策

- 只允许 MIT / Apache-2.0 / BSD 类许可证；禁止 GPL/AGPL 进入核心。
- 依赖数量克制：Windows SDK WinRT 投影 + D3D11 P/Invoke（P0 已验证）、CsWin32（可选）、MCP 官方 C# SDK（若不稳则手写 JSON-RPC）、xUnit（P1 起）。
- 锁定版本；Dependabot 每周；升级需过全量测试。
- 不打包 Edge/Chromium；使用系统已装浏览器。
- 不加遥测 SDK、不加云 SDK。

### 4.4 安全与隐私（开源信任）

- 仅 `127.0.0.1` + 命名管道；token 文件 ACL 限定当前用户；校验 Origin。
- 默认禁用 `attach` 与 `interactive` 输入；开启需配置 + 明确提示。
- 默认不提供整屏截图；只按 target。
- 审计 JSONL；不记录输入文本与截图内容。
- `gs panic` 全局热键；托盘图标状态可见。
- `SECURITY.md` + 私下披露流程；威胁模型写入文档。
- **无遥测**；`gs doctor --bundle` 只在用户主动执行时收集脱敏日志。

### 4.5 工程规范

- `TreatWarningsAsErrors`、nullable、`dotnet format`、EditorConfig。
- Conventional Commits；PR 必须关联 issue；小步提交。
- 单测覆盖 Core 的纯逻辑；集成测试覆盖真实窗口；不追求虚荣覆盖率。
- GUI 集成测试需要交互式会话：GitHub 托管 runner 只跑构建/单测；集成测试用 `scripts/run-integration.ps1` + self-hosted runner（手动触发），结果附在 release。
- 性能基准入仓（BenchmarkDotNet 或自建计时），每次 release 记录数字。
- 混沌测试脚本：杀 daemon、最小化、切虚拟桌面、锁屏、断开显示器。

## 5. 技术栈与构建

| 项 | 选择 | 理由 |
|---|---|---|
| 语言/运行时 | C# / .NET 8 | Win32/WinRT/UIA/COM 互操作成熟；贡献门槛低 |
| 捕获（离屏） | PrintWindow `PW_RENDERFULLCONTENT`（GDI） | P0 实测离屏实时（p50≈12ms）；无需驱动 |
| 捕获（可见/VDD） | Windows.Graphics.Capture + D3D11 | 可见窗口连续帧；VDD 上可全速更新 |
| 观测 | UIA COM (`CUIAutomation8`) | 跨进程、无焦点 |
| Web | 无头 Edge + 最小 CDP 客户端 | 真零窗口；可拿 DOM/console/network |
| 服务 | ASP.NET Core Minimal API + WebSocket | 标准、可测、文档多 |
| MCP | 官方 C# SDK（备选手写 JSON-RPC） | stdio 是 Agent 客户端的主流 |
| UI | WinForms 托盘 + 静态 HTML 状态页 | 无前端构建链；维护成本低 |
| 测试 | xUnit + 自建 FixtureApp | 确定性 |
| 打包 | `dotnet publish` self-contained + zip | 用户无需装运行时 |
| 分发 | GitHub Releases / winget / Scoop | 开源标准路径 |
| 签名 | SignPath Foundation（OSS 免费）优先 | 降低 SmartScreen 摩擦；失败则明确说明 |

**构建命令（目标）**

```bash
dotnet build -c Release
dotnet test
dotnet publish src/GhostScreen.Cli -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true
```

> 不使用 trimming（WinForms/COM 反射易被裁坏）；单文件体积约 70–100MB，可接受。

## 7. 测试策略与兼容性

### 7.1 测试金字塔

| 层 | 内容 | 运行环境 |
|---|---|---|
| 单元 | 坐标换算、稳定性、错误映射、配置、选择策略 | 任意（CI） |
| 组件 | 窗口枚举/停泊/还原（不依赖真实应用） | 交互式会话 |
| 集成 | FixtureApp + 记事本 + Explorer + Edge | 交互式会话 |
| 不变量 | 前台/光标/剪贴板/窗口不在显示器内 | 每次集成 |
| 不可见性 | DXGI 桌面复制逐帧检测 | 本地/self-hosted |
| 混沌 | 杀进程、最小化、切虚拟桌面、锁屏 | 本地脚本 |
| 性能 | 截图/点击/内存/句柄 | 本地基线 |

### 7.2 兼容矩阵（v1.0 目标）

> P1-11 已实测：Edge GUI PrintWindow 完整；VS Code 的 PrintWindow 只有 chrome（需 CDP）；Calculator PrintWindow/UIA 完整但启动抢焦点。详见 `spike/P1-11-REPORT.md`。

| 应用 | 类型 | 捕获 | 观测 | 输入 | 级别 |
|---|---|---|---|---|---|
| FixtureApp | WinForms（自建） | PrintWindow ✅ | UIA | UIA/消息 | ✅ 完全 |
| 记事本 | Win32/WinUI | PrintWindow ✅ | UIA | 消息 | ✅ 完全 |
| 文件资源管理器 | Win32/Shell | PrintWindow（待测） | UIA | UIA | ✅ 目标 |
| 无头 Edge | Chromium | CDP ✅ | DOM | CDP | ✅ 完全 |
| VS Code | Electron | PrintWindow ❌（仅 chrome）/ CDP ✅ | DOM/UIA | CDP | 🟡 需 CDP |
| 计算器 | UWP/WinUI | PrintWindow ✅ | UIA | UIA | 🟡 捕获/UIA 可用，焦点不稳定 |
| 设置 | WinUI3 | PrintWindow（待测） | UIA | UIA | 🟡 待测 |
| Edge（GUI） | Chromium | PrintWindow ✅ / CDP ✅ | UIA/DOM | 优先 CDP | ✅ 捕获；输入优先 CDP |
| Excel | Win32 | PrintWindow（待测） | UIA | UIA | 🟡 单实例需确认 |

**不支持**：最小化/隐藏/其他虚拟桌面、受保护内容、独占全屏、游戏、提权窗口（默认）。

### 7.3 质量指标

- 单元测试：Core 纯逻辑覆盖率 ≥ 60%（不追求数字，关键路径必须有）。
- 集成：每次发布至少在 5 个应用上跑通。
- 基准：截图 p50/p95、点击端到端、内存/句柄；release 记录。
- 24h soak：4 个 target，无增长、无孤儿。
- CI：托管 runner 构建/单测/CodeQL；self-hosted runner 跑集成（手动/定时）。

## 8. 发布与分发

| 项 | 方案 |
|---|---|
| 版本 | 0.x 预发布；v1.0 后 semver；CHANGELOG 自动/半自动 |
| 产物 | `GhostScreen-<ver>-win-x64.zip`、SHA256SUMS、SBOM（CycloneDX）、PDB、LICENSE、THIRD-PARTY-NOTICES |
| 安装 | 解压即用；`gs doctor` 自检；winget/Scoop 清单 |
| 签名 | 申请 SignPath Foundation；未获批则明确写"未签名，SmartScreen 可能提示" |
| 更新 | v1 不自动更新；winget/Scoop/手动下载 |
| 支持 OS | Windows 11 22H2+（22621+）；在 26100/26200 上测试；ARM64 后续 |
| 依赖 | 系统 Edge/Chrome；无 .NET 运行时要求（self-contained） |
| 卸载 | 删除目录 + `gs restore --all`；不写注册表（除可选自启） |

**Release 流程**
1. 冻结范围 → 更新 CHANGELOG/兼容矩阵。
2. 跑全量测试 + 基准 + 24h soak（大版本）。
3. 构建产物、SBOM、校验和；签名。
4. 在干净机器按 Quick Start 验证。
5. 打 tag、发 release、更新 winget/Scoop。
6. 发讨论区/Show HN（仅大版本）。

- **安全**：SECURITY.md，私下披露，72h 内确认（尽力）。
- **Issue 模板**：Bug / Feature / App compatibility；要求版本、日志、截图、复现步骤。
- **PR 模板**：改了什么、怎么测、是否影响兼容矩阵、文档是否更新。
- **Good first issues**：新增 recipe、补文档、加测试、适配一个应用、修一个错误码。
- **治理**：BDFL → 2–3 名 maintainer；重大变更走 issue 讨论，不搞复杂 RFC。
- **节奏**：每月一个小版本；紧急修复随时；不承诺 SLA。
- **可持续性**：可接受赞助，但不做付费功能；范围克制，避免维护者倦怠。
- **翻译**：英文主文档 + 中文；其他语言靠社区 PR。

## 12. 风险与应对（开源视角）

| 风险 | 影响 | 应对 |

| GUI 测试无法在托管 CI 跑 | 质量下降 | 单测覆盖核心；self-hosted runner + 本地脚本；release 附证据 |
| 代码签名成本/门槛 | SmartScreen 警告 | SignPath OSS；否则明确说明 + 校验和 |
| 名称冲突 | 传播受阻 | 发布前检索；备选 GhostFrame |
| 维护者时间不足 | 项目停摆 | 范围克制；good-first-issues；不承诺 SLA；接受"慢但稳" |

## 15. 已定决策（不需要再讨论）

| 决策 | 选择 | 理由 |
|---|---|---|
| License | Apache-2.0 | 专利授权、商业友好、社区常用 |
| 贡献协议 | DCO，无 CLA | 降低贡献摩擦 |
| 平台 | Windows 11 22H2+ x64 | WGC/UIA/CDP 都成熟；Home 可用 |
| 运行时 | .NET 8 self-contained | 用户免装运行时；Windows 互操作成熟 |
| 核心路径 | 离屏停泊 + PrintWindow 主捕获；WGC 可见/VDD | 无驱动、无需管理员 |
| 网页 | 无头 Edge + CDP | 真零窗口；Web 不是壁垒但必须有 |
| 输入 | UIA → CDP → 消息 → SendInput（默认禁用） | 不抢焦点是承诺 |
| 驱动 | 不自研；v1 不捆绑 VDD | 签名/许可/维护成本不可控 |
| 遥测 | 无 | 信任是产品的一部分 |
| UI | 托盘 + 静态状态页；完整 Dashboard 后置 | 维护成本低，先把核心做扎实 |
| UI 语言 | 英文默认 + i18n；提供中文 locale | 开源传播与本地使用兼顾 |
| 发布 | GitHub Releases + winget/Scoop；v1 不自动更新 | 开源标准路径 |
