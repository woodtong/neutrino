## 1. 摘要

GhostScreen（隐屏）是一个 Windows 11 上的**本地、开源、MCP-first 的隐形窗口执行层**：让 Agent 能真实地看和操作原生应用与网页，而人不闪窗、不被抢焦点、不被抢鼠标。

当前实现（0.5.0-dev）：

- **原生窗口**：停泊到虚拟桌面之外；PrintWindow `PW_RENDERFULLCONTENT` 离屏实时截图；DPI-unaware 目标在不感知 DPI 的线程上下文捕获并缩放到物理尺寸；UIA 观测；元素动作消息优先（HWND 子控件 `BM_CLICK`/`WM_SETTEXT`），无 HWND 时走 UIA；默认 strict，人在用时先返回 `USER_ACTIVE`，3 次后弹非激活协商窗，允许/15s 倒计时后 Agent 带 `consent_id` 重试；坐标点击/滚动/拖拽/按键走窗口消息。
- **网页**：私有 headless Edge + CDP；视口/整页/裁剪截图；DOM 观测与 ref 点击；中文输入、组合键、拖拽、滚动；console/network；多视口 snapshot + 横向溢出定位；`attach_cdp` 连接已有 Chromium/Electron 调试端口（VS Code 实测）。
- **生命周期**：崩溃 journal（窗口还原 + 孤儿 Edge 清理）；挂起窗口拒绝与降级；关闭/EOF 全量还原。
- **人机界面**：loopback 状态页（token、卡片、缩略图、急停、单 target 关闭）；独立托盘（状态、target 列表/关闭、打开状态页、急停、退出）；unsigned 安装脚本。
- **接口**：手写 MCP stdio（21 工具）、CLI、状态端点。
- **验证**：32/32 测试（WGC/WPF 焦点/协商门测试默认 opt-in）；100 次 Web 开关压力；单目标与 4 目标 soak；官方 MCP SDK 客户端联调；真实 VS Code `attach_cdp`；安静环境不变量；DPI-unaware 修复前后对比；状态页视觉复核。

**不是**：云桌面、RDP、RPA 平台、驱动、跨平台、商业产品；不注入 DLL、不挂钩 API、不收集遥测、不联网上报。

## 2. 问题、目标与边界

### 2.1 要解决的痛点

Agent 做视觉验证时需要真实屏幕像素和真实输入，但：

- 每次都把窗口弹到人眼前会打断人；
- 人一操作，焦点/光标/键盘又可能打断 Agent；
- 给每个 Agent 配一台显示器或虚拟机不现实。

### 2.2 目标

1. 窗口在系统里**真实渲染**，但不出现在人的显示器上。
2. Agent 能拿到**真实像素**（不是占位图/黑图/冻结帧）。
3. Agent 的输入**不移动真实光标、不抢前台、不碰剪贴板**。
4. 多个 target 可并存；关闭/崩溃后能还原或明确报告。
5. 本地优先：无云、无账号、无遥测；默认安全（移动窗口需确认、不用 SendInput）。

### 2.3 非目标 / 明确不做

- 不打包或自研虚拟显示器驱动（VDD 只做 BYO 检测/说明）。
- 不做云桌面、远程串流、跨平台、移动端。
- 不承诺所有应用；只对支持矩阵内的目标负责。
- 不做商业版功能（付费、账号、遥测、SaaS）。

### 2.4 运行环境

- Windows 11 x64（本机 26200）；.NET 8；PowerShell/Git Bash 构建。
- 交互式用户会话（Session 1）；不做 Session 0 服务。
- 默认非管理员；提权窗口不支持。
- 浏览器：Microsoft Edge（标准安装路径）；无可用的 Chrome 回退。

## 3. 总体架构

### 3.1 进程模型

```
Agent / MCP 客户端（Claude/Cursor/ZCode/...）
        │ stdio JSON-RPC 2.0
        ▼
GhostScreen.Mcp.exe（单进程）
  ├─ TargetManager ── 原生 TargetSession / WebTargetSession
  ├─ ParkingManager ── SetWindowPos/SetWindowPlacement
  ├─ CaptureEngine ── PrintWindow（主）/ WGC（可见兜底）
  ├─ UiaDriver / MessageInput
  ├─ EdgeCdpClient ── headless Edge 或外部 CDP 端点
  ├─ TargetJournal ── %LOCALAPPDATA%\GhostScreen\state\targets.json
  └─ StatusServer ── 127.0.0.1:<随机端口>（token）
        ▲
        │ HTTP 轮询
GhostScreen.Tray.exe（独立小进程，不持有 target）
```

- **MCP 是单进程**：target 生命周期跟随 MCP 客户端。EOF/close_all 会还原/关闭全部。
- **托盘是独立进程**：只轮询状态端点，因此 MCP 退出后显示“未运行”，不能替 MCP 持有 target。
- **没有独立 daemon**：这是当前最大的架构缺口，见 §12。

### 3.2 组件与职责

| 组件 | 职责 |
|---|---|
| `GhostScreen.Core` | `Rect`、截图元数据、`ProductInfo`（版本单一来源）、`StatusClient` |
| `GhostScreen.Windows` | P/Invoke、窗口枚举/描述、停泊/还原、崩溃恢复、FocusGuard、DPI |
| `GhostScreen.Capture` | PrintWindow/WGC、空白/哈希/稳定性、客户区裁剪、PNG 编码 |
| `GhostScreen.Input` | UIA 观测；窗口消息 click/scroll/drag/key/set_text（HWND 子控件） |
| `GhostScreen.Web` | Edge 生命周期、CDP 客户端、DOM/输入/诊断、按键映射、PNG 尺寸 |
| `GhostScreen.Daemon` | `ITarget`/`TargetManager`、原生/Web Session、InputRouter、journal、状态端点 |
| `GhostScreen.Mcp` | 手写 MCP stdio、21 工具、错误映射、状态端点启动 |
| `GhostScreen.Cli` | version/state/list/shot（一次性） |
| `GhostScreen.Tray` | NotifyIcon、状态端点轮询、per-target 列表/关闭、打开状态页/急停/退出 |
| `tests/*` | 夹具、27 个集成/单元测试、Web 压力、soak |

### 3.3 Target 生命周期

```
attach/open_web/attach_cdp
        │
        ▼
     ready ──连续 2 次超时/IsHungAppWindow──► degraded（TARGET_HUNG）
        │                                        │
        │ close                                  │ close
        ▼                                        ▼
     closed（还原窗口/关浏览器/删 profile）
```

- `attach_window` 必须 `confirm=true`；移动窗口前先 `IsHungAppWindow`。
- `ready` 才允许操作；`TARGET_HUNG` 时 capture/observe/input 快速失败，但 close 仍还原。
- 原生 target 写 journal；外部 `attach_cdp` 不写 journal（不拥有浏览器）。

## 4. 关键实测结论（决定架构的部分）

这些结论来自 `spike/` 的真实运行，不是推测。

| 假设/做法 | 实测结果 | 决策 |
|---|---|---|
| WGC 能捕获完全离屏窗口 | **否**：完全离屏冻结在最后一帧（1/20 唯一哈希）；1px 露出也无效 | WGC 只用于可见/VDD；离屏主捕获改为 PrintWindow |
| PrintWindow 离屏可用 | **是**：`PW_RENDERFULLCONTENT` 强制重绘；FixtureApp 8/8 帧变化，p50≈11.9ms、p95≈13.0ms；Notepad 1920×1125 中文完整 | PrintWindow 作为离屏默认后端 |
| 挂起窗口会超时/黑图 | **否**：挂起的 WinForms 仍能返回 DWM 表面旧帧 | 入口用 `IsHungAppWindow` 拒绝，见下一条 |
| `IsHungAppWindow` 随时可用 | **有坑**：`WindowEnumerator.Describe` 会清掉“无响应”标记（同一 hwnd 在 Describe 前 True、后 False） | 检查必须在 Describe **之前** |
| CDP `mouseWheel` 能触发页面滚动 | **否**：headless 下命令成功但页面收不到 wheel 事件 | 改用 `Input.synthesizeScrollGesture(gestureSourceType=mouse)` |
| 整页截图不影响视口 | **否**：`captureBeyondViewport` 与移动端 shrink-to-fit 会留下布局/缩放残留 | 记录“请求视口”，截图后/导航后重新应用；`innerWidth` 是测量值，不当作请求值 |
| UWP 可做到零焦点打扰 | **否**：Calculator 启动可能抢前台 | 明确标记为“焦点不稳定”，不承诺零打扰 |
| DPI-unaware 目标可正常捕获 | **否**：PerMonitorV2 调用方得到物理画布 + 逻辑内容（黑 L 区） | 切 unaware 线程上下文捕获 + `StretchBlt` 到物理尺寸；已修复并测试 |
| 窗口消息能驱动 Chromium | **否**：Chromium/Electron 忽略 `WM_LBUTTONDOWN` 等 | `InputRouter` 拒绝并返回 `INPUT_UNSUPPORTED`；网页用 CDP |
| 输入有按窗口注入的官方 API | **否** | 分层：HWND 消息 → CDP → UIA（自动执行并恢复前台）；默认不用 SendInput |

## 5. 原生窗口路径

### 5.1 枚举与描述

`WindowEnumerator.List/Describe` 用 `EnumWindows`（必要时 `EnumChildWindows`），收集：

- hwnd、pid、进程名、标题、类名；
- 窗口矩形、客户区矩形、可见/最小化/cloaked/tool window；
- DPI 缩放百分比、DPI awareness（`GetWindowDpiAwarenessContext`）；
- 是否 `WDA_EXCLUDEFROMCAPTURE`（DRM/受保护内容）。

`WindowInfo` 是不可变快照；target 创建后会刷新一次。

### 5.2 停泊（Parking）

目标：窗口仍然“显示/非最小化”，DWM 继续合成，但几何上完全在虚拟桌面之外。

1. `GetWindowPlacement` 保存原始位置/显示状态；`GetWindowLongPtr(GWL_EXSTYLE)` 保存原始 exstyle。
2. 最小化窗口用 `rcNormalPosition` 作为原始尺寸，先 `SW_SHOWNOACTIVATE` 恢复。
3. 停车点 = `VirtualScreen.Right + 64`，y 取原 y；这样对所有负坐标/多显示器布局都在虚拟桌面右侧外。
4. `SetWindowPos(SWP_NOACTIVATE | SWP_NOZORDER)` 移过去；追加 `WS_EX_TOOLWINDOW`（隐藏任务栏）和 `WS_EX_NOACTIVATE`（防激活）。
5. 原本隐藏的窗口在同一次 `SetWindowPos` 里加 `SWP_SHOWWINDOW`，避免某些应用（现代 Notepad）在单独 `ShowWindow` 时重置位置。
6. 3 次重试 + `GetWindowRect` 校验完全离屏；失败则还原并抛 `PARK_UNSTABLE` 风格错误。
7. 还原：恢复 exstyle、`SetWindowPlacement`、原本隐藏则 `SW_HIDE`。

**已知风险**：`SetWindowPos` 本身会向目标线程发消息，挂起窗口可能卡住；因此 attach 前先检查 `IsHungAppWindow`。极窄竞态（检查后瞬间挂起）仍靠超时兜底。

### 5.3 焦点安全（0.4.1-dev 修订）

旧版 `ForegroundGuard` 只在操作后 4×40ms 检查并尝试恢复；2026-10-24 实测发现它不可靠：WinForms UIA provider 的 `InvokePattern.Invoke`/`ValuePattern.SetValue` 即使窗口带 `WS_EX_NOACTIVATE` 仍会把前台切到停泊窗口；旧 guard 有时恢复到错误窗口，有时在异步激活前就退出，最终键盘输入落到不可见窗口。

WPF 实测补充：`Invoke`、`SetValue`、`Toggle`、`Select` 都会激活 WPF 窗口；把 `WM_LBUTTONDOWN`/`WM_CHAR` 发给未激活的 WPF 顶层 HWND 不会触发按钮或输入。因此 WPF/UWP 没有通用的“零激活执行”路径；产品选择“执行优先，拒绝兜底”。

现行策略（默认 strict）：

1. **UIA 只做观测**：`Snapshot`/`FindByName`/`FindByAutomationId` 只读，不激活。
2. **动作消息优先**：按 UIA bounds 解析 HWND 子控件，用 `BM_CLICK`/`WM_*`/`WM_SETTEXT`；实测这些消息不改变前台，覆盖经典 Win32/WinForms。消息/CDP 路径永不被门禁阻塞。
3. **无 HWND 走 UIA**：WPF/UWP/自绘控件按可用 pattern 执行（Invoke → Toggle → SelectionItem → ExpandCollapse；文本 ValuePattern）；坐标点击回退到 UIA `AtPoint`。
4. **Human Consent Gate**：`GetLastInputInfo` 最近 2 秒有人类输入时，UIA 动作返回 `USER_ACTIVE`（`retryable`、`attempts`、`max_attempts`、`retry_after_ms`）；第 3 次创建 consent request 并返回 `AWAITING_USER`（`consent_id`、`expires_at`）。托盘弹出**非激活**协商窗，允许/拒绝 + 15 秒倒计时；倒计时结束自动授权。Agent 带 `consent_id` 重试同一 target/action/element 才执行。票一次性、绑定具体元素、授权后 30 秒过期；拒绝 `USER_DENIED`。
5. **`FocusGuard` 恢复**：执行时最多等 500ms 观察激活；若前台仍是 target，用 `SetForegroundWindow`/`AttachThreadInput` 恢复，并做 100ms 稳定校验；人类已切到第三个窗口则尊重；恢复失败返回 `FocusRestoreStatus.Stolen`，MCP 以 `FOCUS_STOLEN` 警告上报，但动作已执行。
6. **balanced/force**：`balanced` 直接执行 + `FocusGuard`；`force` 不等待；用 `GHOSTSCREEN_INTERACTION_POLICY` 切换，不是默认。
7. **strict_no_focus_steal=true**：连协商都不做，需要 UIA 时直接 `FOCUS_STEAL_NOT_ALLOWED`。
8. **最后兜底**：控件没有任何可执行 pattern → `ELEMENT_NOT_ACTIONABLE`；目标挂起/受保护/不可见沿用既有错误码。

限制：WPF/UWP 的 UIA 动作会造成短暂焦点切换；strict 通过协商窗把决定权交给自然人，但协商窗本身也是一次打扰。`balanced`/`force` 会直接切前台；不能承诺 100% 不打断。真正的零打扰需要应用提供非激活 API、独立会话/桌面，或微软开放 Agent Workspace 级隔离。

### 5.4 捕获引擎

`CaptureEngine.Capture(hwnd, options)`：

1. **入口先查 `IsHungAppWindow`**（必须在 `Describe` 前），命中抛 `TARGET_HUNG`。
2. `Describe`：无效/最小化 → `NOT_RENDERABLE`；受保护 → `PROTECTED_CONTENT`。
3. `visible = Visible && 不完全离屏`。
4. `PrintWindowCapture.TryCaptureWithTimeout`：
   - 在**专用后台线程**执行 GDI 兼容 DC + `PrintWindow(PW_RENDERFULLCONTENT)`；
   - `Wait(timeoutMs)` 超时则放弃该线程，返回 `CAPTURE_TIMEOUT`；
   - `GetDIBits` 取 32bpp top-down BGRA；空白检测（采样颜色范围 ≤2）。
5. PrintWindow 失败/空白且窗口可见 → WGC 兜底；WGC 也只接受非空白帧。
6. 稳定性：在 `WaitStableMs` 预算内按 50ms 采样，比较哈希直到稳定。
7. 默认 `IncludeFrame=false`：裁剪到客户区，图像坐标 = 客户区像素。
8. 元数据：backend/尺寸/窗口/客户区/client_origin/DPI/stable/blank/hash/时间。

**注意**：PrintWindow 对“挂起但仍有 DWM 表面”的窗口会返回旧帧；入口检查是唯一可靠拦截点。`WindowEnumerator.Describe` 会清除 hung 标记，所以顺序不能反。

**DPI-unaware 目标**：当 `DpiAwareness=Unaware` 时，PrintWindow 工作线程先 `SetThreadDpiAwarenessContext(DPI_AWARENESS_CONTEXT_UNAWARE)`，拿到逻辑尺寸的完整窗口；再用 GDI `StretchBlt(HALFTONE)` 缩放到物理窗口尺寸，最后按物理客户区裁剪。这样坐标仍是物理像素，图像不再有黑 L 区。本机 150% 下单屏验证：修复前 1024×650 画布内容只占 680×400，修复后 1020×630 铺满、黑像素 <10%。混合 DPI 双屏仍需第二块屏验证。

### 5.5 挂起降级

`TargetSession.Capture`：

- `CAPTURE_TIMEOUT` 连续 2 次 → `degraded / TARGET_HUNG`；
- `TARGET_HUNG`（来自 IsHungAppWindow）→ 立即降级；
- `EnsureOpen` 对 capture/observe/click/scroll/drag/key/set_text 全部抛 `TARGET_HUNG`，不再创建超时线程；
- `close` 不经过 EnsureOpen，仍可还原窗口；重新 attach 可恢复。

生产环境一次超时最多遗留 1 个阻塞线程，降级后封顶 2 个。**per-target 长驻 worker 决定不做**：PrintWindow 已有专用线程，attach 已拒绝挂起窗口，再加队列/取消/COM 线程模型复杂度收益不足。

### 5.6 输入

`UiaDriver`：

- `Snapshot` 遍历 UIA 树，返回 ref/role/name/AutomationId/bounds/enabled/focused/patterns；
- 每次 observe 递增 epoch；`click_element` 使用最新 ref，过期返回 `ELEMENT_STALE`；
- `Invoke`/`InvokeByAutomationId`/`SetValue` 以及 `Activate`（Invoke/Toggle/SelectionItem/ExpandCollapse）用于无 HWND 的自动回退；执行后由 `FocusGuard` 恢复前台（见 5.3）。

`MessageInput`（经典 Win32/WinForms）：

- 元素动作：按 UIA bounds 找最深 HWND 子控件；按钮 `BM_CLICK`，其他可交互控件发鼠标消息，EDIT/RICHEDIT 发 `WM_SETTEXT`；
- 客户区点 → `ClientToScreen` → 用子窗口枚举找到最深子窗口 → `SendMessage(WM_LBUTTONDOWN/UP)`；
- 滚轮 `WM_MOUSEWHEEL`、拖拽 `WM_MOUSEMOVE` 序列、按键 `WM_KEYDOWN/UP`；
- `MapVirtualKey` 生成 scan code，扩展键设置 lParam bit 24；
- Chromium/Electron 被 `InputRouter` 拒绝（`INPUT_UNSUPPORTED`），避免“命令成功但页面没反应”。

**没有使用 SendInput**：它需要真实前台/光标，违背产品目标；未来若提供，必须显式 interactive 授权。

### 5.7 崩溃恢复

`TargetJournal`：

- 路径：`%LOCALAPPDATA%\GhostScreen\state\targets.json`；
- park/open_web 成功后写入；先写 `.tmp` 再 `File.Move(overwrite)`；空 journal 删除文件；
- 原生记录：hwnd、pid、进程名、窗口类、标题、`WINDOWPLACEMENT`、原 exstyle、是否可见；
- web 记录：浏览器 pid、进程启动时间、profile、URL。

启动时 `Recover()`：

- 原生：`IsWindow` + pid + 类名三重校验，然后恢复 exstyle/placement/可见性；任一不符跳过并记录原因；
- web：只有 pid + 启动时间（±2s）+ 进程名 `msedge` 都匹配才杀进程，防 pid 复用；杀后删 profile；
- 清扫 `web-profiles` 下 24h 以上目录；
- 损坏 journal 移到 `.corrupt-<ts>`，不阻塞启动；
- journal 写失败 → `STATE_WRITE_FAILED`，撤销本次 attach/open（避免“以为可恢复、实际没记账”）。

**单进程假设**：两个 MCP 实例共享同一 journal 会互相清理；多客户端 daemon 需要按实例分区。

## 6. 网页路径

### 6.1 Edge 生命周期

`EdgeBrowser.LaunchAsync`：

- 固定安装路径发现 Edge（Program Files (x86)/Program Files/LocalAppData 的 Edge/Beta/Dev）；
- 启动参数（`ArgumentList`，无 shell）：`--headless=new`、`--remote-debugging-port=0`、独立 `--user-data-dir`、`--window-size`、`--hide-scrollbars`、`--mute-audio`、禁用后台节流、`about:blank`；
- 端口：轮询 profile 下的 `DevToolsActivePort` 第一行，不解析 stderr；
- **目标 URL 不进入命令行**：固定从 `about:blank` 启动，导航走 CDP；只接受 http/https/file/about，拒绝 `-` 开头；
- 关闭：`Browser.close` → 杀进程树 → 删 profile（重试 5 次）；
- 可执行文件有 allow-list，`IsKnownEdgePath` 只允许固定安装根下的 msedge。

### 6.2 CDP 客户端

手写 `ClientWebSocket` + JSON-RPC 2.0：

- 请求 id → `TaskCompletionSource`；响应/事件分流；
- 事件：console 缓存（500 条）、Network 在途计数/失败/4xx/5xx（200 条）、点击/滚动/输入；
- 超时：`SendAsync` 的 `WaitAsync`；
- 没有第三方 SDK 依赖，便于自包含发布。

### 6.3 导航与等待

`Page.enable`/`Runtime.enable`/`Log.enable`/`Network.enable` → `Page.navigate`：

- 轮询 `document.readyState === "complete"`；
- `document.fonts.ready`；
- 网络静默：最多 3s，要求 300ms 无在途请求；长轮询/WebSocket 不会让导航失败；
- 重置 page scale；
- 重新应用“请求视口”（不是测量到的 innerWidth）。

### 6.4 截图

`Page.captureScreenshot`：

- 默认视口；
- `full_page`：`Page.getLayoutMetrics` 的 `cssContentSize`，超过 16384px → `CAPTURE_TOO_LARGE`；
- `clip {x,y,width,height}`：CSS 像素，与 full_page 互斥；
- 截图后恢复请求视口（`captureBeyondViewport`/shrink-to-fit 可能留下布局缩放）；
- 元数据 `region` = `viewport|full_page|clip`。

**坐标约定**：web 的 click/scroll/drag 是 **CSS 像素**；截图是设备像素（`image = css × dpr`），元数据同时给 `css_width/css_height`。

### 6.5 DOM 观测与 ref

`GetInteractiveElementsAsync`：

- 选择器：`button, a[href], input, textarea, select, [role=button], [contenteditable=true], [onclick]`；
- 过滤零尺寸；
- 返回 tag/id/role/text/placeholder/bounds/稳定 CSS path/enabled；
- ref = `e1..eN`，每次 observe 新 epoch；`click_element` 点击时重新取中心，滚动后仍有效；ref 过期 `ELEMENT_STALE`。

### 6.6 输入

- click：`Input.dispatchMouseEvent` mouseMoved/Pressed/Released；
- drag：按下后按步长移动，再释放；
- scroll：`Input.synthesizeScrollGesture`（mouse），因为 `dispatchMouseEvent(mouseWheel)` 在 headless 不产生页面 wheel 事件；
- key：`Input.dispatchKeyEvent`，支持 Ctrl/Shift/Alt/Meta 与 F1–F24/方向键等；文本键在无修饰时带 text；
- set_text：React 兼容的 native setter + `input`/`change` 事件；中文已实测。

### 6.7 诊断与 snapshot

- `console`：`Runtime.consoleAPICalled`，级别/文本；
- `network`：`Network.loadingFailed` 与 4xx/5xx，含 url/type/error/status；
- `snapshot`：最多 6 个视口；每个视口截图 + `horizontal_overflow/scroll_width/inner_width` + 最多 5 个越界元素（selector/bounds/right）；结束后恢复原视口；
- 移动端超宽内容会触发 shrink-to-fit，`innerWidth` 可能大于请求宽度；溢出判断以实际 `innerWidth` 为准。

### 6.8 `attach_cdp`（外部 Chromium/Electron）

- 连接已运行的 `--remote-debugging-port` 端点，按可选 `page_url` 子串选页面；
- 返回 `kind=web`、`external=true`、`process=null`；
- 不启动、不关闭浏览器；`close_target` 只断 CDP；
- 外部浏览器被杀：`IsConnected=false` → 后续操作 `TARGET_CLOSED`；close 仍安全并清理 profile/journal（外部 target 不写 journal）。
- 适用：VS Code/Electron 这类 PrintWindow 只有 chrome、必须 CDP 的应用。

**实测范围**：`attach_cdp` 用真实 headless Edge 端点验证连接/导航/截图/detach；2026-10-24 又用 **VS Code 1.142（Electron 43）** 实测：独立 profile + `--remote-debugging-port=9223` 启动，官方 MCP SDK 客户端 `attach_cdp { port: 9223, page_url: "workbench" }` → 截图 115KB PNG → observe 30 元素 → `close_target`；detach 后 VS Code 仍存活。VS Code 的 PrintWindow 仅 chrome、CDP 完整这一结论来自 P1-11 spike。

### 7.2 状态端点（loopback）

- `GET /?token=`：静态 HTML（1s 状态轮询 + 5s 缩略图）；
- `GET /api/status`：版本/pid/uptime/恢复摘要/targets；
- `GET /api/screenshot?target_id=`：PNG（原生 2s、web 6s；hung 409、超时 504）；

- 不写 PATH、不注册服务、不改 MCP 客户端配置；未签名，SmartScreen 可能提示。

### 7.4 CLI

`GhostScreen.Cli.exe version|state|list|shot`；`shot` 先停泊、截图、还原；移动别人窗口必须 `--confirm`。

## 9. 失败模式与降级

| 场景 | 行为 |
|---|---|
| 窗口最小化/隐藏/cloak | `NOT_RENDERABLE`（attach 会尝试恢复最小化窗口） |
| `WDA_EXCLUDEFROMCAPTURE` | `PROTECTED_CONTENT`，不尝试绕过 |
| 挂起窗口 | attach 前 `TARGET_HUNG`；运行中 `IsHungAppWindow` 立即拒绝；连续超时降级 |
| PrintWindow 挂起 | `CAPTURE_TIMEOUT`；2 次后 `TARGET_HUNG` 快速失败；close 仍还原 |
| PrintWindow 空白 | 可见窗口回退 WGC；仍空白则失败，不返回黑图 |
| WGC 离屏 | 已知冻结，不用于离屏；只用可见/VDD |
| Chromium 消息输入 | `INPUT_UNSUPPORTED`，改用 `open_web`/`attach_cdp` |
| UWP 抢焦点 | 明确标记“焦点不稳定”；不承诺零打扰 |
| DPI-unaware | 已修复（单屏 150%）：unaware 线程上下文捕获 + 物理缩放；混合 DPI 双屏仍待测 |
| 外部浏览器被杀 | `TARGET_CLOSED`；close 安全；profile 清理 |
| 窗口被销毁 | capture 明确失败；close 安全；journal 清理 |
| journal 损坏 | 移到 `.corrupt-*`，继续启动 |
| journal 写失败 | `STATE_WRITE_FAILED`，撤销本次 attach/open |
| CDP 连不上 | `CDP_CONNECT_FAILED` |
| 页面导航超时 | `NAVIGATION_TIMEOUT`（readyState 未 complete） |
| 整页过大 | `CAPTURE_TOO_LARGE`（>16384px） |
| 状态端点无 token | 401 |

## 10. 质量与安全

- **无遥测、无账号、无云**；状态页/托盘都只连本地 loopback。
- **attach 必须 confirm**；不提供静默接管。
- **默认不用 SendInput**；不动光标/剪贴板；无 HWND 的 UIA 动作自动执行，由 `FocusGuard` 恢复并上报失败；`strict_no_focus_steal` 可改为拒绝。
- **不注入 DLL、不挂钩 API、不装驱动**。
- **URL 策略**：http/https/file/about；拒绝 `-` 开头；URL 不进命令行。
- **Edge 可执行文件 allow-list**；参数经 `ArgumentList`、`UseShellExecute=false`、无 shell。
- **状态端点 token**：每次启动随机、固定时间比较、只绑 loopback；端点文件在用户 LocalAppData。
- **journal**：只在本机；profile 删除；不记录截图内容。
- **未签名**：SmartScreen 可能提示；发布包提供 SHA256。
- **已知信任边界**：同用户进程可读 `status.json`/journal；MCP 本身拥有同等权限。

## 12. 未能完成的部分、所需支持与原因

以下不是“再写点代码”就能证明完成的；按影响排序。

### 12.1 24 小时 soak（P4-05）

- **现状**：harness 已完成；单目标/4 目标各 3 分钟、100 次 Web 开关均通过。
- **为什么不能在这里完成**：这是墙钟时间；一次会话无法等待 24 小时并验证“无持续增长”。
- **需要什么**：一台可连续运行 24h 的 Windows 11 机器（或 CI 的交互式桌面 runner），保持登录/不锁屏；运行
  `GhostScreen.Soak --minutes 1440 --interval 30 --native 2 --web 2`，导出 JSONL 曲线。
- **为什么**：句柄/内存泄漏、浏览器进程累积、journal 增长只有在长时间尺度才暴露；3 分钟只能证明没有快速泄漏。

### 12.2 4 target 混沌（杀进程/最小化/切桌面/断网）

- **现状**：死窗口、被杀浏览器、CDP 断连已有测试；杀进程/最小化可做，锁屏/切虚拟桌面会打断当前桌面。
- **为什么不能在这里完成**：锁屏/切换虚拟桌面/断网会影响你正在使用的会话，不能安全自动化；部分场景需要独立测试机。
- **需要什么**：专用 Windows 测试机/VM（可锁屏、可切桌面、可断网），以及允许重启/杀进程的授权。
- **为什么**：焦点/会话隔离是产品承诺的一部分，必须在真实桌面状态下验证。

### 12.3 混合 DPI / 双屏 / 锁屏唤醒（P4-04）

- **现状**：负坐标虚拟桌面布局/停车点有单测；`dpi_awareness` 元数据已输出；DPI-unaware 修复已在单屏 150% 验证；物理屏只有一块 2560×1600。
- **为什么不能在这里完成**：150%+100% 双屏的点击命中、跨屏停车、锁屏/唤醒恢复，需要第二块物理屏或虚拟显示器；单屏无法真实复现 Per-Monitor DPI 的坐标映射。
- **需要什么**：第二块显示器（不同缩放）或已安装的 IddCx VDD；以及允许修改显示设置/锁屏的测试环境。
- **为什么**：混合 DPI 的坐标错误通常只在跨屏边界出现，单元测试无法覆盖 Win32/DWM 的真实行为。

### 12.4 DPI-unaware 修复的剩余验证

- **已解决（单屏 150%）**：独立 unaware 线程夹具 + `SetThreadDpiAwarenessContext(UNAWARE)` + `StretchBlt` 到物理尺寸；修复前后 1024×650 黑 L 区 → 1020×630 铺满，自动测试通过。
- **仍不能在这里完成**：100%/125%/150% 混合 DPI 下的缩放质量、双屏跨屏点击命中。
- **需要什么**：第二块不同缩放的显示器，或可切换缩放的测试环境。
- **为什么**：修复的缩放因子来自当前系统/窗口 DPI；混合 DPI 下每个窗口的缩放不同，必须在真实跨屏场景验证。

### 12.5 VDD（虚拟显示器）

- **现状**：未实现/未测试。
- **为什么不能在这里完成**：需要安装 IddCx 虚拟显示器驱动（管理员、驱动签名/测试模式），项目明确不捆绑驱动。
- **需要什么**：用户自装 VDD（如 Parsec VDD/虚拟显示器驱动），或提供可安装驱动的测试机；然后验证 WGC 在该显示器上的连续帧。
- **为什么**：这是驱动/内核层能力，超出用户态工具的范围；也是产品“BYO VDD”的定位。

### 12.6 真实干净机器验证

- **现状**：复制到 `%TEMP%`、PATH 去掉 dotnet 的近似验证通过。
- **为什么不能在这里完成**：没有全新 Windows 安装/VM；无法验证 VC++ 运行库、SmartScreen、权限、Edge 缺失等真实首启问题。
- **需要什么**：一台干净 Windows 11（无 .NET/无开发工具）或 Windows Sandbox/VM；按 README 从解压到 MCP 连接走一遍。
- **为什么**：自包含发布只能证明“不依赖 dotnet”，不能证明新用户环境的所有依赖。

### 12.7 代码签名 / SmartScreen

- **现状**：未签名；提供 SHA256。
- **为什么不能在这里完成**：没有代码签名证书（OV/EV）或 OSS 签名服务账号。
- **需要什么**：CA 证书或 SignPath/GitHub OSS 签名服务；以及签名流水线。
- **为什么**：签名是证书与身份问题，不是代码问题；未签名会被 SmartScreen 拦截。

### 12.8 真实 MCP 客户端（Claude/Cursor/ZCode）

- **现状**：官方 MCP SDK 客户端联调通过；配置文档齐全。没有修改你本机的 Claude/Cursor/ZCode 配置。
- **为什么不能在这里完成**：需要各客户端的账号/配置/重启；擅自改用户配置属于越界。
- **需要什么**：你选择 1–2 个客户端，按 `doc/08` 添加 server；或提供测试账号/配置目录。
- **为什么**：不同客户端对工具 schema、图片 content、超时/重连的处理有差异，SDK 通过不等于每个客户端 UI 都通过。

### 12.9 8 应用兼容矩阵

- **现状**：FixtureApp、Notepad、Edge GUI、VS Code（spike）、Calculator（spike）有证据；矩阵未补齐。
- **为什么不能在这里完成**：需要安装/启动更多应用（Explorer、7-Zip、Office、聊天工具等），部分会抢焦点或需要许可证；逐个验证会反复移动窗口。
- **需要什么**：明确的目标应用清单与测试机；允许启动/移动这些应用。
- **为什么**：兼容性是按应用行为逐个验证的，不能从 Fixture 推导。

### 12.10 独立 daemon / 多客户端 / 暂停恢复

- **现状**：单进程 MCP；托盘已有 per-target 列表/关闭，但没有暂停/恢复、登录自启；仍是轮询状态端点。
- **为什么不能在这里完成**：需要先做架构决策（named pipe/HTTP、多客户端、生命周期、安全模型），工作量和风险都大；不是单点补丁。
- **需要什么**：产品决策 + 时间；若做，建议先设计 daemon 的权限/生命周期/多实例 journal 分区。
- **为什么**：当前“关掉 MCP 就不能查看/急停”的限制来自单进程模型；托盘轮询只是过渡方案。

### 12.11 状态页 2–5fps 连续缩略图

- **现状**：0.2fps（5s）。
- **为什么没做**：原生截图会强制重绘，2–5fps 对被动状态页成本高；当前优先低打扰。
- **需要什么**：明确的使用需求与性能预算；可用增量编码/限流/按需开启。
- **为什么**：这是产品取舍，不是技术阻塞。

### 12.12 winget / Scoop 分发

- **现状**：已有 zip + SHA256 + `scripts/install.ps1`（unsigned 便携安装/卸载、开始菜单快捷方式）。
- **为什么没做**：winget 提交需要公开 GitHub Release、稳定 URL 与（通常）签名；Scoop manifest 也需要公开归档地址。在仓库尚未公开/未发布前做会产生不可用清单。
- **需要什么**：公开 GitHub 仓库/Release、签名证书（可选）、winget 提交授权。
- **为什么**：分发渠道依赖发布身份与公开产物，不是本地代码问题。

## 13. 结论

GhostScreen 0.4.1-dev 已经证明了一条可行路径：**停泊 + PrintWindow 离屏实时捕获 + 窗口消息（UIA 自动回退并恢复前台）+ 私有 headless Edge/CDP + 外部 CDP attach**。经典 Win32/WinForms 的消息动作不激活窗口；WPF/UWP 的 UIA 动作会短暂激活，但能恢复前台。产品优先保证 Agent 调用成功，拒绝只作为“控件不可操作/目标不可用/用户选择 strict”时的最后兜底。

它的强项是：

- 离屏原生捕获的实时性（PrintWindow p50≈12ms）和可验证的不可见性；
- 网页路径的完整度（截图/整页/裁剪/snapshot/溢出/console/network/输入/外部 CDP）；
- 崩溃恢复、挂起拒绝、死目标保护等可靠性细节；
- 27/27 测试、100 次压力、单/4 目标 soak、官方 SDK 客户端联调；
- 本地优先、无遥测、默认安全的边界。

它的边界也同样明确：**单进程、单屏、无驱动、未签名**。24h soak、混合 DPI、VDD、干净机器、真实客户端与 8 应用矩阵需要时间、硬件、驱动或证书；这些已在 §12 逐项列出所需支持与原因。把它们包装成“已完成”是不诚实的，当前版本停在 `0.4.0-beta` 是刻意选择。
