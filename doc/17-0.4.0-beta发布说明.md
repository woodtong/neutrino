## 新增

### DPI-unaware 捕获修复

- 问题：PerMonitorV2 进程捕获 DPI-unaware 窗口时，PrintWindow 返回物理尺寸画布，内容只占左上角（1024×650 中 680×400），右侧/底部大片黑色。
- 修复：对 `DpiAwareness = Unaware` 的目标，在**不感知 DPI 的专用线程上下文**里捕获（`SetThreadDpiAwarenessContext(UNAWARE)`），再用 GDI `StretchBlt(HALFTONE)` 缩放到物理窗口尺寸；客户区裁剪与坐标保持物理像素。
- 验证：独立线程创建的 DPI-unaware 夹具，修复后截图为 1020×630、内容铺满、黑像素 <10%，文字可读；有自动测试（28/28）。
- 仍不承诺混合 DPI 双屏（需要第二块屏/VDD）。

### 托盘 per-target 列表与单目标关闭

- 状态端点新增 `POST /api/close_target?target_id=`（token 必填，404/500 明确）。
- `StatusClient` 解析 targets（id/title/kind/state/degraded_reason），新增 `CloseTargetAsync`。
- 托盘菜单新增 `Targets` 子菜单：列出每个 target（标题 · 状态 · degraded_reason），点击确认后关闭该 target；无 target/未连接有明确占位。

### 真实 VS Code `attach_cdp` 验证

- VS Code 1.142 以独立 profile + `--remote-debugging-port=9223` 启动后，官方 MCP SDK 客户端完成：`attach_cdp { port: 9223, page_url: "workbench" }` → 截图（115KB PNG）→ observe（30 元素）→ `close_target`（detach）。
- `close_target` 后 VS Code 仍存活；外部应用生命周期不被 GhostScreen 接管。

### unsigned 安装脚本

- `scripts/install.ps1`：把发布目录复制到 `%LOCALAPPDATA%\GhostScreen\app`，创建开始菜单“GhostScreen Tray”快捷方式；`-Uninstall` 删除应用与快捷方式，保留 MCP 配置/journal/web profile。
- 不修改用户 MCP 客户端配置、不写 PATH、不注册服务。
