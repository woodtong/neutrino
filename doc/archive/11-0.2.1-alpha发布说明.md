## 本版新增

### 整页与裁剪截图

- `screenshot` 新增 web-only 参数：
  - `full_page: true`：按 `Page.getLayoutMetrics` 的 CSS 内容尺寸截整页；超过 16384px 返回 `CAPTURE_TOO_LARGE` 并提示改用 clip。
  - `clip: {x,y,width,height}`：按 CSS 像素裁剪任意区域，与 `full_page` 互斥。
- 元数据新增 `region`（`viewport` / `full_page` / `clip`）与 `clip` 坐标。
- 截图后会恢复调用方的视口；`captureBeyondViewport` 留下的页面缩放会被重置。

### 多视口 snapshot + 横向溢出诊断

- 新工具 `snapshot { target_id, viewports[], full_page }`：
  - 一次返回多个视口的 PNG（默认 390×844@2 移动、768×1024、1440×900）。
  - 每个视口附 `horizontal_overflow`、`scroll_width`、`inner_width`，以及最多 5 个越界元素（selector/bounds/right）。
  - 结束后恢复原视口。
- 实测：400px 窄视口能检出 480px 元素溢出并定位到 `#wide`；900px 视口无溢出。

### network 失败诊断

- 新工具 `network { target_id, limit }`：返回 `Network.loadingFailed`（连接失败、DNS、文件缺失等）与 HTTP 4xx/5xx，最多保留 200 条。
- 与既有 `console` 一起覆盖前端最常见的一类问题。

### 稳定性

- 新增 `tests/GhostScreen.WebStress`：反复 `open_web → screenshot → close`，统计句柄、托管/私有内存、profile 与浏览器进程退出。
- 100 次循环实测：0 失败；托管内存约 0.9MB 持平；私有内存 32–38MB 持平；句柄在 30 次后稳定在 362；`%LOCALAPPDATA%\GhostScreen\web-profiles` 始终为 0。
- network idle：导航在 readyState=complete 后等待最多 3s 的网络静默（300ms 无在途请求）；长轮询/WebSocket 不会让导航失败。

## 快速开始

配置与 0.2.0 相同，见 `docs/MCP-CLIENTS.md`。网页视觉验证示例：

```text
open_web { url: "http://localhost:3000", width: 1280, height: 800 }
snapshot { target_id }
screenshot { target_id, full_page: true }
console { target_id }
network { target_id }
close_target { target_id }
```

`snapshot` 的返回顺序：第一段 text 是 JSON（每个视口的尺寸、hash、溢出诊断），随后是各视口 PNG，顺序与 `shots[].index` 一致。

## 已知限制

- 整页截图受 Chrome 16384px 限制；超长页面需分段 clip。
- 元素裁剪只接受坐标，不接受 selector（可先用 `observe` 取 bounds）。
- network 只记录失败与 4xx/5xx，不提供完整请求/响应体。
- 跨域 iframe 的 DOM/网络事件覆盖有限。
- 移动端 emulation 下，超宽内容会触发 shrink-to-fit，`innerWidth` 可能大于请求宽度；`snapshot` 的溢出诊断以实际 `innerWidth` 为准。
- 未在真实 MCP 客户端与干净机器验证；未签名。
