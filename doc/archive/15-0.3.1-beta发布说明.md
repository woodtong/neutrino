## 新增

### `attach_cdp`（21 个 MCP 工具）

- 连接**已经在运行**的 Chromium/Electron DevTools 端口，不启动、不关闭浏览器。
- 参数：`port`（1–65535）、可选 `page_url` 子串用于选择页面。
- 返回 target：`kind=web`、`external=true`、`process=null`；`screenshot/observe/click/set_text/key/scroll/drag/navigate/viewport/console/network/get_html` 全部可用。
- `close_target` 只断开 CDP 连接（detach），不会杀浏览器；浏览器由用户/原应用管理。
- 典型用法：VS Code 以 `--remote-debugging-port=9222 --user-data-dir=<临时 profile>` 启动后，`attach_cdp { port: 9222 }`。
- 连接失败返回 `CDP_CONNECT_FAILED`。

### 死目标保护

- 浏览器被外部杀掉后，后续操作返回 `TARGET_CLOSED`（不再落到 `INTERNAL`）。
- 目标窗口被销毁后，capture 失败但仍可 `close_target`，journal 条目清理，不会卡住。
- 新增测试覆盖“窗口消失”和“浏览器被杀”两条路径。

### WGC 连续帧

- 可见窗口连续 8 次 WGC 截帧，断言至少 4 个不同哈希，验证不是冻结帧（P1-04 可见路径证据）。

## 验证

- 测试 **27/27**；构建 0 warning / 0 error；format 通过。
- `attach_cdp` 用真实 headless Edge 端点验证：连接、导航、截图、关闭后浏览器仍存活。
- 死目标：窗口销毁、浏览器被杀均明确报错/安全关闭、profile 清理。
- 0.3.0-beta 的崩溃恢复、挂起拒绝、状态页、托盘、soak 结果保持不变。

## 已知限制

- `attach_cdp` 只支持 Chromium 系（Edge/Chrome/Electron），不支持 Firefox/WebKit；不管理外部浏览器生命周期。
- VS Code 只在 headless Edge 上验证了同一协议路径，未重新跑真实 VS Code 窗口。
- 托盘仍无 per-target 列表/暂停恢复/自启。
- 24h soak、4 target 混沌、第二块屏/混合 DPI、DPI-unaware 修复、VDD、干净机器与签名仍未完成。
